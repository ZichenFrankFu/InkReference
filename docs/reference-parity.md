## 上游 schema 与事实来源复核

本次通过 `git ls-remote origin HEAD` 只读核对远端，HEAD 与上述审计提交一致；未改变固定的复用验证检出。本次重新读取了上游 `storage/reference_schema.py`、`knowledge/reference_db.py`、参考页实际挂载组件与对应路由。上游使用普通 SQLite 表和作品级 JSON，并没有独立的“人物属性历史”关系表。章节标签是文本证据的位置，和故事发生时间、数据库修改时间分别保存。

| 上游表／结构 | 实际职责 | InkReference 采用的设计 |
|---|---|---|
| `reference_works` | `ref_id` 主键、作品元数据、评分／喜欢原因、全文与预处理状态；剧情、角色、设定、风格、节奏、分卷等 JSON；叙事／纯设定模式 | 素材作品保留外部 ID；全文及分析拆为独立存储，通过明确 ID 关联，分析写入仍有 revision 和人工审核 |
| `reference_chapters` | `(ref_id,number)` 主键；持久化已确认的章节目录、原始标题、解析章号、卷名、正文、原文范围；另有场景／embedding 缓存 | 区分目录顺序与原文章号；采用不可变正文版本及可重建章节读模型，已运行分析继续指向原版本 |
| `reference_entries` | 一部作品的摘录／用户笔记，区分场景、人物、设定、对白、技巧、气氛等类型，保存来源与位置 | 本应用素材与关系模型独立实现；没有将此表整体复制为摘录库 |
| `project_reference_links` | 将参考作品／摘录用于某个写作项目，维度为 `world/character/plot/style/mood` | 不属于本应用当前的作品／人物／桥段关联；未移植写作项目注入接口 |
| `work_index_progress` | `(ref_id,level,backend)` 保存 L1 摘要、L2 章节、L3 原文向量索引的分级进度与断点 | 未复制该向量索引体系；数据库字段筛选不等同于语义检索 |

人物字段为 `name/role_tag/intro/mentions/first_chapter/first_seen_at`，并兼容 `speech_samples/appearance_chapters/appearance_word_count`。`appearance`、`personality`、`experiences` 都是 `[{chapter,text}]`：一项事实保留一处章节锚点，不把性格或外貌覆盖成一个最终值。设定为 `category/title/content/first_chapter/first_introduced_at/updates[{chapter,text}]`，分类包含力量体系、势力组织、地理、社会规则、历史、世界观、其他。

剧情为 `epochs → periods → events`，事件字段为 `subject/category/name/description/first_chapter/time_marker/time_markers`。`first_chapter` 指向首次出现的文本章节；`time_marker` 和 `time_markers` 表示故事内时间；`created_at/updated_at` 才是数据库操作时间。上游 `CharactersAndSettingsExtraction.tsx::CharacterCard` 的实际经历读取规则是：人工／已存 `experiences` 非空时优先，否则按剧情事件 `subject` 与人物名的精确匹配补充显示；不是注释所说的始终从剧情重新生成。不能把派生补空写回为重复的第二份经历。

上游 `referenceMerge.ts` 对人物按姓名合并，对设定按分类与标题合并，逐章事实按 `chapter + text` 去重；人物提及数累加、简介取较长值、角色定位按优先级、首次章号取较早值。InkReference 保留丰富事实数组与首次出现信息，但改为服务端合并、幂等贡献和人工标量优先，避免重新提交同一段时反复累加，或较长的新摘要覆盖人工编辑。

上游 `UnifiedExtractionPanel.tsx` 每段一次调用同时提取事件／人物／设定／风格，分别记录四节完成状态；按字数聚合风格，再从逐章信号派生节奏。它的批量路径直接提交全部四节，且只要存在某个分段 ledger 就跳过；本应用保留批处理，要求人工审核，并逐节判定完成。上游 `prompts.py` 要求推断具体故事日期，`resolveEventTimeMarkers` 还会继承前一绝对日期；本应用不继承这一推断要求，原文不明确时保留未知或相对时间。

## 页面与作品

叙事型作品的实际 7 个 tab 来自 `ui/frontend/src/pages/ReferenceLibraryPage.tsx` 的 `WorkDetailTab` / `TABS`：**原始文件、预处理、特征提取、剧情大纲、角色、设定、文本特征**。

这是上游审查基线。InkReference 把文件来源和预处理统一放入“文本清理”，依次为**元数据、分卷与章节、正文清理**；当前“参考作品分析”只浏览**剧情大纲、角色、设定、时代背景事件、语言分析**，任务运行与候选审核独立到“提取任务管理”。章节识别、清洗和版本操作继续由全文工作区提供。

纯设定作品使用 `ui/frontend/src/components/reference/PureSettingPanel.tsx` 的 `PURE_SETTING_TABS`：**原始文本、设定、角色、特征提取、设定特征**。旧注释中的“快捷输入”不是当前实际 tab 文案。创建作品时选择 `structure_type=setting_collection` 才进入该模式。

| 编号 | 实际上游能力 | 复刻目标 / 验收 |
|---|---|---|
| W01 | 搜索、媒介类型筛选、作品列表、星级、单个及批量删除 | 作品应能独立定位，不按同名合并；作品级数据、正文和分析保持关联 |
| W02 | 新建作品：名称、作者、媒介、题材、喜欢原因、评分、叙事/纯设定 | 保留作品元数据；未知字段与 v8 CSV 不被覆盖 |
| W03 | 作品摘要：状态、全文、时间段/事件/角色/设定数、按已提交四节计算的章节处理进度 | 数量与审核提交结果一致，未审核内容不计已完成 |
| W04 | 评分、为什么喜欢、按章笔记 `{chapter,text}` 新增/编辑/删除 | 可保存和重新打开；按章排序不改变原始备注 |

## 原始文件与章节预处理

源文件：`FilesPanel.tsx`、`PreprocessPanel.tsx`、`ui/backend/app/routers/reference/works.py`、`ui/backend/app/routers/reference_api.py`、`reference_pipeline/chapter_parser.py`、`reference_pipeline/preprocess_jobs.py`。

| 编号 | 实际上游能力 | 复刻目标 / 验收 |
|---|---|---|
| D01 | 首次上传、覆盖全部、追加文件；上传文件清单、逐文件内容、删除文件、清空 | 续传创建新版本，原先章节及不可变原件仍可追溯；新正文确实接在末尾 |
| D02 | UTF-8 / GB18030 严格解码；TXT 正文 | GUI 接受 TXT、PDF、EPUB；后两者先转 TXT，再解析章节；保留不可变来源，不静默丢失无法解码字符 |
| D03 | 扫描章节格式候选，给出匹配数/置信排序；用户确认一个或多个格式后识别 | 能识别 `第N章/回/节`、`Chapter N`、`N、`、`N.`、中文/全角数字；混合格式不重复切分 |
| D04 | 自定义 `N` 格式模板或高级正则、启用/禁用及预览匹配 | 格式变更前可预览；无匹配时全文仍完整覆盖，不丢前言与结尾 |
| D05 | 无编号缩进对比、独立“作者说章节”、分卷标题识别 | 标题与正文边界准确，首字不能被消耗；重复章号用稳定 ID 区分 |
| D06 | 作者说关键词配置及恢复默认；整章作者说评分/原因 | 显示原因与章节标记，用户决定整章是否清理 |
| D07 | 正文章内题外话段落：扫描、逐条预览、默认勾选、手动取消后批量删除 | 每章同一正文内红色标注候选删除；点击/键盘可保留；保存只移除选定原文区间 |
| D08 | 乱码检测、自定义检测模式、尝试编码还原及逐章兜底；仍无法修复单独标记 | 缺字/替换符和可疑乱码显示不同于题外话的颜色；禁止把缺字自动“猜对” |
| D09 | 长度异常、兼容历史拆分标记、已编辑、已清题外话、缺章提示 | 章列表有语义颜色及可访问标签；异常是提示，不擅自删正文；当前上游已移除自动拆分长章 |
| D10 | 手动逐章编辑正文、仅改标题、在本章后插入、删除本章；缺章处插入 | 正文直接编辑，修改后显示未保存与保存入口；新版本只改变目标章或当前字符切片；并发旧版本提交冲突；非 BMP 字符的偏移不出错 |
| D11 | 多选章节删除、整章作者说批量清理；撤销上次清理 | 不可变版本提供更完整撤销；相同候选重复操作幂等 |
| D12 | 保存全部已识别章节、已存章节概览、导出清洗后全书 TXT | 所有章节均参与，不只当前预览页；原始来源保留供追溯，GUI 只提供清洗后 TXT 导出 |
| D13 | 识别后台任务状态/阶段、暂停/继续/取消、日志 | 有进度；章切换使用缓存/局部叠层，不能插入加载条挤压正文 |
| D14 | 分卷自动建议、LLM 检测、手工编辑卷号/标题/章范围、插入/删除卷 | 分卷边界明确且全覆盖；支持复制分卷 prompt 与粘贴 JSON 后确认 |

上游段落检测并不是“出现月票就删除”：`detect_aside_paragraphs` 跳过明显人物对话和较长叙述；依据短段落的元叙事关键词、章末位置、末尾分隔线评分。每个候选同时保留 `text`，在应用时核对实际文本，避免只按可能过期的段落序号删除。

上游 `runAll` 会直接提交四节，且任意 ledger 项存在就跳过该段。InkReference 应修正这两个行为，保留人审和逐节完成判断，不照搬其缺陷。上游粘贴解析的激进字符串修补也不应静默改变事实内容。

## 复用边界与验收记录

复用的是 MIT 上游的章节规则、提取声明、合并/统计思路和实际业务操作。新应用继续使用不可变正文版本、SQLite、LangGraph、本地凭据、可审核提交；不复制上游全局模型路由、直接覆写正文、只保存一次撤销、静默解码失败和前端非事务写多个 JSON 字段的限制。具体代码来源与改动见 `THIRD_PARTY_NOTICES.md`。

本轮必须进行的验收包含：续传与逐章 CRUD 的文本覆盖测试；误报段落取消清理后保留；所有章候选范围有效；表情/罕见字代码点偏移；并发旧版本拒绝；分节审核幂等；分段与全书视图数据相同；纯设定导入导出往返；真实 API 浏览器中连续切章无布局位移；蓝色主题及异常色语义；Windows/macOS CI。真实商业模型/OCR 未运行时需分别注明，不能由合成模型测试推断质量。

输出合同 4 与历史 1／2／3 分别固定；新模型请求、人工粘贴、缓存和审核都携带对应合同，不以更改旧 prompt 的方式强制升级旧任务。真实模型抽取质量、网络来源事实及自动语义阈值仍需独立验收；结构／回归和合成 HTTP 结果只说明代码与流程行为。

本轮追加的本地 Ollama embedding 下载、多模型资料 A/B、章节范围并集／复用和提取 A/B 也为 InkReference 本地代码。下载复用 Ollama `/api/pull` 与 `/api/embed` 协议，不分发权重；资料组保留最多四份原稿并生成独立审核副本，热度／桥段评分比较使用当前库公式；提取组固定同源 scope 和不同实际阶段目标。它们不属于 InkOctoBot 已移植索引、自动事实核实或上游模型评测系统。章节重叠只在完整已审块可复用时跳过调用，旧大块的部分重叠保留提示并独立提取。

提取对照使用独立 `execution_scope_mode:"comparison"`，同一原始 scope、相同初始记忆及独立模型输出，不借用普通任务的 partial 状态。分区和整体入库都必须先采纳；同一 run 在多组复用时明确 group ID，已有正式贡献则锁定采纳模型。此为本地事务／公平比较规则，与上游章节标签事实积累分别处理；合同 4 的全书 Y 统一包含缺章占位，不因选择局部范围而变化。

## V13：统一决策交互与维护边界

本轮不重新定义剧情、角色、设定和语言 Schema，也不复制第二套 InkOctoBot 工作台。沿用已审查的来源证据、稳定 ID、章节范围、独立审核和人工标量保护，在相同业务适配器外统一自动／半自动／手动交互。作品资料、分卷、四阶段提取、快捷修复、大纲整理和资料翻译分别保留自己的输入绑定、预览、编辑及确认事务；手动模式通过字段模板组织输入，不要求配置模型。

共享能力目录与回复解析、结构化日志和诊断 ID、SQLite 增长索引、用量分页及本地 R 图标为 InkReference 自有实现，不称为上游已有功能的直接移植。无入口的独立转换页和旧文件／预处理面板删除，转换、旧设定集、历史 Skill／Workflow／Schema 与兼容 API 保留。React Flow 运行时依赖退场，旧布局数据不因此删除。

当前实际缺口继续包括逐上传来源范围删除、可验证的乱码编码恢复、上游摘录库／写作项目注入和 L1／L2／L3 索引；本轮三模式并不自动补齐这些功能。更大规模存储、全文／向量索引、真实模型校准及原生系统验收的优先级见 [review-v13.md](review-v13.md)。
