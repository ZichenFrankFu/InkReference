# InkReference 架构

React/TypeScript 工作台通过同源 `/api` 与 FastAPI 通信。Windows PowerShell 与 macOS shell 入口共用 `scripts/manage.py`，源码默认在项目 `.venv` 安装和启动；开发者可显式复用自行配置的环境，Conda 并非依赖。`--desktop` 用 pywebview 打开 Windows WebView2 或 macOS WebKit 原生窗口，浏览器入口复用相同服务。打包后收集 Python 和前端运行依赖，用户无需安装开发环境。启动器仅允许回环地址，默认 `127.0.0.1`。界面使用固定阶段卡片配置分析，旧 React Flow 布局数据兼容保留；CSS 动画处理过渡，并尊重 reduced-motion。

外观支持浅色、深色和跟随系统。`theme.ts` 在 React 挂载前应用配色，`theme.css` 统一覆盖工作区、表单、编辑器与弹窗；选择保存在浏览器 `localStorage` 的 `inkreference.appearance`，默认跟随系统，并响应系统主题变化及跨窗口 `storage` 事件。外观偏好不写入业务数据库。顶部不再重复显示工作区面包屑，保留侧栏展开／收起按钮。模型配置集中在侧栏工作区，取消全局右上角重复入口；侧栏底部保留备份与恢复，并提供快捷修复与外观选择。

## 本地安全边界

HTTP 中间件检查所有请求的回环 Host，API 的读写请求都拒绝外站／`null` Origin 及浏览器 cross-site 请求。默认仅允许同源前端；开发时可通过 `INKREFERENCE_DEV_ORIGIN` 显式增加一个回环来源。Vite 代理仍携带浏览器 Origin，因此开发时也需配置该例外。API 与 HTML 使用 no-store，生产页面 CSP 限制脚本、连接和资源来源，并附带 MIME、referrer 和 frame 限制。CDN 文档页停用，接口结构保留为本地 `/openapi.json`。该服务面向单用户本机使用，不提供局域网监听或多用户认证入口。

素材、全文、转换与规则清洗均在本机处理。模型连接分为 `local` 与 `remote`：local 只接受 localhost／字面量回环地址；remote 强制 HTTPS。用户主动点击测试连接或读取模型列表即执行该操作，不追加确认。新建远程分析时 GUI 只确认一次目标服务与模型，任务保存已确认目标，之后开始／恢复不重复弹窗；提交时仍校验目标指纹，阻止其他窗口修改配置造成无声外发。页面加载或应用重启不触发外发模型请求。

## 数据与版本

应用数据在 Windows 默认使用 `%LOCALAPPDATA%\InkReference`，macOS 使用 `~/Library/Application Support/InkReference`；`INKREFERENCE_DATA_DIR` 或 `--data-dir`／`-DataDir` 可指定另一目录。同一工作区通过系统级文件锁限制一个应用实例，防止另一个端口上的进程错误恢复仍在运行的任务。

| 数据库 | 内容 |
|---|---|
| inkreference.sqlite3 | 作品、角色、桥段三类主记录及结构化 ID 关联、关联读索引、旧字段归档、手工素材关系、revision 墓碑和分析幂等入库记录 |
| workbench.sqlite3 | 不可变全文原件及清洗版本、统一上传处理任务、转换任务、模型配置、逐请求用量、分析任务与块级结果 |
| skills.sqlite3 | 不可变声明式 Skill 版本 |
| workflow_definitions.sqlite3 | 不可变工作流定义、旧画布布局兼容数据；新版固定阶段配置 |
| checkpoints.sqlite3 | LangGraph 状态与中断 checkpoint，禁用 pickle 和任意模块构造 |

上传原件作为字节与 SHA 保存，清洗生成新版本。疑似乱码保留并定位；不能恢复的文字不假装修复。明确的原文、清洗版本、字符范围和块覆盖状态可以追溯。所有范围采用 Unicode codepoint，前端按后端分页读取，避免 UTF-16 偏移错误。大文本不一次挂载到编辑控件。

不可变版本作为审核与 LangGraph 的权威快照；每部文本保留最近 10 个普通版本，另外保留初始版本、当前版本与被任务／审核／清洗完成记录引用的版本。旧格式缺少来源列表时，其必要祖先链也会受保护。超过上限的普通历史在新版本提交时裁剪；旧库启动不扫描全库历史。保留的分析历史 ledger 也保护其引用原文。原始上传字节、解码文本与 source mode 独立保存，普通来源和上传回执不永久钉住整书版本；其 nullable 版本引用可随普通历史裁剪清空，幂等回执仍避免重复补充。`doc_version_meta` 保存 `has_source_provenance`、`active_source_ids_json` 及文本长度等小字段，避免裁剪和来源列表反复解析全文 payload 或读取原件 BLOB。`doc_sources` 以独立 `mode` 保存上传方式，`version_id` 可为空并在旧普通版本删除时置空。章节读模型仅常驻最近 3 版，旧保留版本打开时按需重建。`doc_version_views` 与 `doc_chapter_views` 存放可重建的摘要、章节目录和逐章文本／问题读模型。工作区进入时只取版本摘要，目录不带正文；切章只查询相应章节，问题弹窗和历史按需加载。读模型布局版本为 5，旧缓存首次访问时事务重建；直接保存也先保证缓存版本正确，避免新规则沿用旧提案。新版本保存 `preprocessing_version:2`；缺少标记且关键词恰等于旧完整默认列表的历史快照，在派生视图中扩展 `PS：` 默认规则。自定义列表和空列表保持原样，新标记也保留用户主动从默认列表移除 `PS：` 的选择。重建不修改不可变正文版本，后续读取复用。兼容的完整版本接口仍保留，不用于正文工作区的常规加载。

主库迁移版本为 6，与可移植导入文件的格式版本分开管理。主记录为 `works`、`characters`、`cliches`，均以外部 ID 为主键，保存字符串字段、revision 和顺序。作品只保留当前作品元数据与关联视图，剧情补充说明和典型桥段剧透不再是当前字段；旧字段保存在 `legacy_values`，用于兼容迁移。界面的“看过”对应现有 `用户是否完整体验过` 存储字段，点击更新也检查 revision。

| 存储结构 | 权威数据与约束 |
|---|---|
| `works.values_json` | 作品、类别、作者、发布日期、看过、剧情梗概、讨论热度／商业规模区间；旧热度保留兼容；按 ID 关联作品／角色／桥段 |
| `characters.values_json` | 人物 ID、角色名、别名、定位、性格基调、视觉元素、初始／阶段状态；共用 `character_contract.py`，不同作品状态由 context 隔离 |
| `cliches.values_json` | 独立 `clichéID`、内容与派生 cliché 评分；`人设塑造`、`剧情机制` 各为独立单选字符串；按 ID 保存作品／角色关联 |
| `library_links` | 从主记录关联 JSON 在同一事务重建的查询索引，保留来源字段、位置、目标 ID 和完整关联对象；不是另一份可独立编辑的事实来源 |
| `material_relations` | 用户额外建立的有类型／说明／metadata 的关系，保留 revision 与端点校验 |
| `character_contexts` | `(character_id,work_id)` 到文档／提取 ID 与共享角色 JSON 的明确绑定；单独 revision，双向修改同时核对目录及参考分析 revision |
| `catalog_field_archive` | schema 4／5 已删除字段的兼容归档，不覆盖最早 v8 `legacy_values` |
| `work_cliches`／`legacy_values` | 前者提供旧接口的派生关联，后者归档迁移前可见字段（含当时由权威关系派生的反向列），不随后续现代编辑改写；新格式不要求用户手填这些内部兼容表 |

关联 JSON 可以携带目标 ID、作品名与关联内容等字段，不能只显示“有关联”。输入的双向声明按目标 ID 校验，冲突明确报告，不按同名或共同出现推断关系。桥段互相关联、自关联和缺失目标禁止。删除作品时按关联规则清理目标引用，保留仍独立存在的角色；旧 `characters.work_id` 仅作兼容提示，现代角色使用空值。旧 v8 完整三表仍可迁移，当前导入契约以最新三表字段为准。

桥段分类在 CRUD 和导入层共用严格枚举：人设塑造为强大／智谋／利他／共情／利己／执念／反差／宿命，剧情机制为信息反转／机械降神／顿悟突破／代价交换。两维独立，各允许空值，展示时组合为带维度的标签。主库从 schema 4 迁移时只为现代桥段补齐两个空字段，不改已有 revision、归档内容或关联。角色定位、关联作品及桥段两维筛选在 SQL 层执行后再分页；候选作品以 ID 和标题投影返回，不加载文本或分析。信息页只编辑非关联字段，声明关联和手工关系集中在关联页，后端与导出仍保留权威关联 JSON。

`doc_documents.work_id` 是文本到作品的显式外部链接，一部作品可以绑定多部文本；不得按书名自动合并。`catalog_completions(document_id,work_id,version_id,completed_at)` 固定“完成清洗”时的文本版本。关联／完成操作同时核对原作品 ID 和最新版本 ID，避免另一个窗口的更新被覆盖。已关联文本的作品删除仍受保护。

作品详情通过 `catalog_links.py` 按需读取文本摘要与分析数量；数量由 SQLite JSON 查询计算，不把所有分析内容加载到 Python 计数。只有打开对应分析时才读取丰富事实。`reference_analysis` 仍以 document 为中心，`reference_section_commits.source_version_id` 保存每次已审核贡献的原文版本；作品字段不重复存储剧情、人物、设定的第二份 JSON。只打开空分析产生的 revision 0 不算已有分析；贡献来源与当前文本版本不同则标记过期，保留旧分析而不冒充新版结果。

新版参考分析采用内容 Schema 3，独立于主库 schema 6。`chronicle_schema.py` 与 `character_contract.py` 定义严格输出：平面事件具有名称、主题、描述、0–100 叙事进度及可选故事时间，角色使用初始状态和事件关联的完整阶段快照，设定支持 `earlier_setting_id` 与追加内容快照。阶段范围为开始／结束进度，持续阶段结束为空。用户界面不再暴露披露章号、排序键或修正链；原文证据、来源版本与 codepoint 偏移仍在内部核验。模型阶段不能缺省证据，手工商业资料允许明确的 manual origin，不伪造原文证明。

`analysis_projection.py` 根据事件生成两种时间视角及卷／全书大纲：叙述线按进度和实际偏移，故事线对明确可比较的日期排序，未知／相对时间保持叙述位置。按进度的只读投影过滤未来事实并派生当前快照，不能覆盖全量原记录。旧 v2 与章节数组、`epochs → periods → events` 保存原结构并以副本适配；预览 API 不写库。最早 source 角色状态用于初始状态，手工初始状态优先；新 source 阶段可闭合先前开放范围，手工范围不自动改写。

`character_bridge_v11.py` 将文档中的稳定角色 ID 显式导入／绑定到全局人物 ID，随后按作品隔离快照。绑定后，参考分析保存钩子与人物 context 更新通过附加数据库的同一事务同步；身份字段变化也传播到明确绑定对象。首次绑定不按姓名猜测，重复 ID 必须明确选择复用；作品关联、目录 revision、context revision 与参考分析 revision 均受校验。人物库和作品分析不再维护相互漂移的两套字段。人物与桥段权威关联在更新时反向同步，不以共同出现推断额外关系。 可移植素材库保留原 source/extracted ID；目标工作区缺少文档时 context 明确标记缺失，只离线编辑目录快照，不创建幽灵分析。源存在但绑定不符则停止并要求重新绑定。完整源文与分析迁移使用项目备份。

桥段评分由唯一命中作品的热度权重占全库热度的比例计算，范围 0–100。讨论热度和商业规模的 1–10 区间取中点再平均；缺失分项按 1，并报告缺失数量，旧有效单热度兼容。它是本库加权普及程度，不是全网商业或讨论的自动实测值。旧常见程度／命中统计字段归档而非继续作为 GUI 指标。

## 全文工作流与界面

`IngestionStore` 将 TXT、PDF、EPUB 的上传接入统一的持久任务：TXT 严格解码；PDF／EPUB 复用转换服务得到 TXT，然后进入同一章节识别和问题扫描。阶段回调报告实际处理进度，无法量化的阶段显示不定进度；重启将未完成任务标为中断，重试由用户触发。来源与目标参数固定，幂等记录处理提交成功但任务状态未及时写回的情形，避免重复导入。

顶部上传创建新全文；选定作品后的上传按钮固定当前作品与基准版本，选择“更新正文”替换全部正文或“补充章节”接到末尾，无需再次指定保存位置。两处作品列表统一命名“参考作品库”，显示书名、一位小数的万字数与作品类别；搜索支持标题、作者、类别，不再显示源文件格式。两种上传均新增版本并保留历史来源。处理时目标已更新则以 409 拒绝覆盖。GUI 中转换设置只随相应文件出现，没有单独的转换页；工作区按“原始文件 → 正文清理 → 分卷与章节”排列，原件下载入口从界面移除，后端兼容 API 仍可读取历史原件。

正文工作区组合无复选框的章节目录、标题输入、正文编辑和集中图例，删章为带无障碍名称的常驻垃圾桶按钮，标题旁不再重复放置切章箭头。章号／标题只在标题栏展示；正文阅读模型排除标题与分隔换行，并折叠重复空行。`source_offset_map` 将展示文本的 codepoint 映射回精确章节内范围，编辑提交另带原始切片 `expected_text`；同次请求可原子修改标题及一页正文，章节边界与未显示的正文保持不变。删除真实章节后按同一编号序列递减后续章号；保留原有缺号和各卷编号重启，删除重号副本且同号仍在时不重复减号。修改仅作用于章号和所删区间，不重新拼装其余正文。常规保存复用未改章节的识别结果、诊断和字符统计，只重算修改章；调整识别设置时先生成不落盘预览，目录变化必须选择保留旧版或以新版为准，提交再次核对预览 token 与基准版本。重识别整体替换新目录，不把新旧分章拼接；目录／文本／设置均无变化时复用原版本，不额外积累历史。连续同章号且前项正文为空时可提出重复标题修复，保留有效正文及已有纯标题；两项都有正文时仅标记，不自动合并。差异预览先缩小到改动附近的上下文，限制复杂逐行比较的范围。

红色删除建议、紫色字符问题和空章提示集中在同一区域，目录使用整项高亮，缺章虚拟项以独立颜色和文字状态区分。标题与正文以原有文本叠加精确标记，不可见字符另加可见线标，避免改变编辑布局。红色、紫色命中片段共用定位入口，可跳至标题范围或正文实际分页；切页后核对编辑器的源范围才设置选区。标题求订阅／求月票等明确提示与正文候选共用 proposal ID、Unicode 范围和选择式清理；`scope` 区分标题与正文，标题编辑单独接收本地范围。默认非正文关键词包含 `PS：`，显式保存的自定义关键词不被默认值覆盖。结构异常提供具体原因而不虚造正文标记。批量弹窗按章节展示实际命中片段并提供勾选／全选；问题总数按受影响章节统计。所有章节的问题从 findings 读模型按需读取，不单设诊断 tab。编辑产生脏状态与保存入口；切章、离开与批量清理保护未保存草稿。窄屏工具栏换行和区域重排避免按钮挤压。“完成清洗”检查作品关联并固定完成版本，再提供 TXT 导出；导出入口不常驻正文工具栏。章节识别与正文标记规则默认折叠，进度统一放在页面标题下，空闲时不使用右上角任务弹窗重复反馈。

`chapter_layout.py` 生成规范显示名、正文布局与缺章目录。缺号逐章生成零长度虚拟项，例如 11→17 之间显示 12、13、14、15、16 五项；用户补写时才将该章实际插入新版本。缺号问题由这五个占位项表示，不再在第 17 章重复计数。真实章节的源偏移、ID 和已有任务索引不因虚拟项改变；分卷标记与编号重启划分独立序列，真实重号保留并标记。异常巨大的章号间隔有数量上限，剩余范围明确展示，避免巨量内存分配。新增／重命名标题在提交前验证仍可独立识别，失败不写入版本。最终清洗 TXT 的正文内及章节之间均使用单换行，仍未补齐的章保留空标题；精确版本下载接口独立保留。

分卷的读取、保存、提示词和检测优先使用版本摘要及每章至多 200 codepoint 的章头查询；范围只统计真实章节，虚拟缺章占位不成为分卷端点。原始来源列表也只读元数据，不为显示来源重新获取整书版本。

分块属于 LangGraph 的内部分析计划；全文 GUI 保留开始分析与任务进度，不暴露单独的分块按钮。“参考作品分析”集中查看剧情大纲、角色、设定、时代背景、语言分析；“任务管理”作为独立页面负责运行、进度、候选与审核。参考分析与任务页的全局任务列表使用摘要接口，不批量读取历史候选；选定作品单独补查摘要，历史深链接也先读取对应摘要。新版全书分析不为展示已有结果请求候选；只有用户打开分段或浏览旧版段结果时，才按所选且已审核来源任务惰性读取完整 run。文件来源、章节识别与清洗统一在文本清理工作区操作。顶层导航不再使用独立横条；侧栏承担收展，窄屏菜单进入标题行。加载用页面／弹窗标题下的呼吸进度轨，已知工作量时显示实际进度，不弹出右上角加载浮层；减少动态效果时禁用呼吸动画。

## 逐章文件投影

`chapter_storage.py` 在数据目录 `books/<safe title>/` 生成当前正文的逐章 UTF-8 TXT 与 `metadata.json`。书名用于目录；Windows 保留名、跨平台非法字符和超长名称受约束，同名作品通过文档 ID 后缀分开。元数据独立 revision，包含作者、作品类型和保留原精度的最早更新时间；上传首部明确标记可供初值，未知日期为 null，导入时间另存。

SQLite 不可变正文与 `doc_book_metadata` 为权威；文件为派生投影，不读取磁盘人工修改来隐式覆盖正文。`doc_storage_pending` 持久登记待发布版本；正文提交后在临时目录写入内容哈希文件，最后原子替换清单。失败保留已提交正文与旧清单，可显式校验／重建；下次请求不伪造写盘成功。小编辑复用未改文件和元数据，只读取／编码修改章。旧应用文件只有仍匹配上一清单哈希才删除，额外文件／用户修改保留。改书名退役旧目录时同样只清理已验证应用文件；历史版本不复制成多套文件夹。

章节 ZIP 从选定保留版本生成；按清单合并各章与规范全书清洗 TXT 一致，包含空缺章标题。完整项目备份不重复包含逐章文件，恢复数据库后在新工作区重建；SQLite 版本和原件继续承担恢复与审计责任。

## 语言分析与时代背景

`language_analysis.py` 提供 Unicode 非空白字符口径的本地统计：句长、段长分布与标点每千字频率，计算覆盖全部已识别章节正文并排除标题，保存计算方法、覆盖范围与来源版本。段落是非空物理行，句边界为句末符号与省略号，统计含标点；新版不要求词汇多样性。风格、视角、修辞、对白、惯用表达、命名和叙述构成是模型／人工判断；高潮、爽点、伏笔、节奏和情绪保留章节证据，不将它们包装为确定性的文学质量分数。

`era_background` 区分网络梗和真实事件，保存标题、具体内容、大致时间，以及具有叙事进度／可选故事时间的逐次出现点；出现点显式关联事件和角色。旧结束日期、精度和核实状态不进入新业务合同。频次从已审核原文位置去重；角色玩梗只计算网络梗的对白／心理，平均包括零使用者，按每万字归一需要有效覆盖字数。这描述已提取使用，不能保证召回、起源日期或外网热度。另一个联网资料流程读取外部来源，但不自动更改正文时代分析。

## 联网资料与语义去重

`research.py` 使用独立真实 LangGraph：search → fetch → draft → dedup → review。设置、任务、消息、来源、草稿和有限向量缓存保存在现有工作台数据库，服务按需初始化；历史列表单次摘要 SQL，选中任务才读内容。Tavily／Brave 使用各自 API Key，SearXNG 需要 JSON 搜索；明确本机 SearXNG 可用 HTTP，其余远程连接要求 HTTPS。搜索与页面抓取分开，页面有公网地址、重定向与大小限制，脚本剥离后只提供有限摘录；已读取状态不等于语义事实已核实。

整理模型只能使用本次已取回来源，作品身份要求同时出现作品名和作者；候选最多主角与一名配角、三个桥段。热度范围必须附实际来源与换算依据，依据不足保留 null，无法证明全网排名时给出 warning。用户可聊天补充、编辑草稿并明确选择更新／新增，目录变更需重新匹配；`apply_research` 用 job ID 幂等，在一个素材事务内更新三类表及反向映射，不触碰正文与正文特征。

`semantic_search.py` 真正调用兼容 `/embeddings` 或 Ollama `/api/embed`，以内容哈希及 embedding 目标指纹缓存有限向量，进行精确余弦检索；没有向量就失败，不以关键词相似伪装向量搜索。阈值 0.90 建议复用、0.78 人工比较，所有入库决定仍由用户确认；高度相似的新增需确认，同批高度相似的两个新增会被阻止。阈值是实现启发式，尚未由真实语义匹配数据集校准。聊天与 embedding 分别记账，搜索服务的请求费用不换算成模型 token。远程目标仅开始确认一次，任务恢复检查同一固定指纹；不会继承更改后的模型／搜索地址。

## 转换与模型

EPUB 转换复用安全 spine 读取、markdownify 和 markdown-it-py。PDF 通过独立可信 Python 子进程调用 MinerU 4 SDK，输入文件路径仅作为参数，不通过 shell。默认全文原生文本解析；扫描件 OCR 需要独立准备的模型。FULL Markdown 渲染保留可能被标为页眉的正文。转换输出的 TXT 自动进入上传任务的章节识别，已有 Markdown／TXT 输出 API 保留。子进程支持取消，关闭时先终止全部进程树；任务恢复需要用户操作。

ModelService 通过 HTTPX 连接原生 Ollama 或 OpenAI-compatible Chat Completions 服务（含本地 LM Studio/vLLM）。GUI 提供本地／商业服务预设、手填地址和模型、显式模型列表读取、当前草稿测试和可折叠参数。草稿测试使用固定消息，不保存草稿或读取全文。

凭据层支持 `session`、`vault`、`environment`：会话 Key 只在内存；环境变量只保存名字；系统密钥库通过 keyring 的批准操作系统后端保存，按工作区路径隔离。密钥库不可用时失败关闭，允许用户改选会话或环境变量，禁止明文／第三方后端回退。读取配置只返回凭据状态，保存响应、模型快照、前端浏览器存储及备份不包含 Key。恢复到新目录后重新配置凭据。清除凭据会移除会话／保险库内容与环境变量引用，不修改系统环境变量。

每次真实请求及重试都有独立账本，进程中断的请求标为结果／费用未知。提供商实际计数、规划预估、未知值独立记录，价格与币种由用户配置。保存模型配置本身不会调用模型；任务确认绑定固定目标而非整个配置的未来地址。

## 快捷诊断与源码修复

`diagnostics.ts` 在前端内存保留有限的请求失败与 JavaScript 错误；后端中间件记录请求模板、状态、耗时和异常栈位置，不自动记录请求体、头信息、异常消息、正文或模型响应。`quick_repair.py` 在用户点击后组合环境／依赖版本、Git 信息、脱敏事件和按功能选取的源码窗口，生成 `inkreference.repair.v1` 提示词；用户自行复制给模型，应用不会外发诊断。上下文有数量和长度限制，截取会明确标记。

`repair_routes.py` 提供生成、解析预览、异步应用、进度、历史、导出与回滚。方案仅接受声明式文件替换及原始 SHA-256，预览不写文件，应用前再次检查全部哈希。仅允许现有业务源码与脚本，排除目录越界、符号链接、依赖清单、修复引擎、数据库及凭据；模型不能传入待执行命令。修复保存原始字节备份，写入后编译检查 Python、解析 JSON；前端使用固定 TypeScript/Vite 入口在临时目录构建，随后发布新资源。Shell／PowerShell 脚本不会自动执行。

源码修复和回滚使用同一串行操作槽，阶段进度可轮询。失败恢复本次写入，重启后从持久清单重新展示近期操作；恢复先验证全部备份，再接受各文件处于修复前或修复后的已知哈希状态，遇到后续修改则停止。记录及备份位于数据目录的 `quick-repairs`，不写入业务数据库。诊断会话与预览仅在内存存活两小时；跨环境导入方案须显式绑定当前新会话，并保留严格文件校验。

打包版没有可修改的源码树，因此提供诊断、预览和方案导出；源码开发环境在相同版本上核对并应用。后端及脚本改动需重启，前端构建成功后可刷新；运行中的 Python 不热替换模块。独立的章节缓存重建 API 只从不可变全文版本重建派生读模型，不修改正文历史，也不依赖源码修复能力。静态检查和构建通过不等同于模型方案的功能正确，应用后仍须复测原操作。

v3 分块优先已保存卷界，累积完整章节至较大的预算范围；超卷或超长单章才继续拆分。原文范围连续无重叠，绝不截尾。每阶段按实际模型上下文预留固定 Schema、系统、实体记忆与输出，默认 100000 字符／128000 输入／12000 输出上限与 800000 任务预算仍受模型能力约束。`chunk_groups` 保存显示卷名和真实章范围，内部块及请求台账保留。无章节作品一次扫描各块的非空白字符计数计算进度，避免每个事实重新读取全书。

旧 1.0／1.1／2.0 声明及任务 snapshot 不改写；v2 canonical 调用显式 `version=2`，四阶段 prompt 与既有版本逐字一致。v3 使用同合同阶段 Skill，跨代缓存以 contract version 隔离，不能把旧候选当作新格式。

## LangGraph 与审核

StateGraph 执行 prepare → extract → validate → advance 循环，最终进入人工 review。执行上下文显式禁用 LangSmith tracing 与父级追踪，避免继承外部环境开关上传正文或模型响应。新版 `default@3.0.0`／`unified-reference@3.0.0` 固定执行剧情大纲、角色、设定、语言分析四阶段；时代背景属于语言阶段输出。每阶段遍历选定全部源块，再进入下一阶段。`fixed_pipeline.py` 管理阶段候选与有限上下文；StageGraph 内部仍使用持久 prepare／extract／validate／advance 节点。Agent／Skill 可改变阶段提示要求、模型覆盖、输出上限、预算及兼容的 Skill 版本，不能改变拓扑或输出字段；旧 1.0／1.1／2.0 定义保留。分块优先使用不可变快照的真实解析章节边界（包含自定义标题规则），没有章节信息时才用正则兜底，超长章再以段落为界，连续覆盖、无重叠。预算按各阶段模型容量预留系统提示、规范 Schema、输出与自适应实体记忆，记忆上限 6000 codepoint；短上下文包含 ID、名称、短事实和邻近事件，不重复发送整书累计分析，也不泄露未来事件／情节线／状态摘要。未来角色／设定仅可提供 ID／名称作身份对齐，后文摘要为空。四阶段仍分别覆盖正文，不宣称固定比例 token 节省；预算不足在请求前停止。

任务固定全文版本哈希和工作流、Skill、默认及阶段模型快照。阶段模型未配置时继承任务模型；远程目标集合一次确认，并按阶段 fingerprint 验证，恢复也不能被已修改地址／模型重定向。每块先持久化响应，再验证结构及精确引文；checkpoint 间隙恢复会复用已保存响应，避免重复请求。失败、取消和关闭都保留状态，重开不自动请求模型。待审核结果只能显式修订；revision 检查防止覆盖别人的修改，已进入人工审核的任务不能被恢复执行覆盖。

`run_stage_cache` 是独立、可丢弃的完全匹配候选缓存，最多 1000 条／32 MiB；键包含完整请求（源文、Schema、上下文）、模型快照与输出上限。命中后仍验证结构、链接及证据，并重绑当前来源版本／绝对偏移；人工候选修订不缓存。缓存命中在任务尝试中单列 `local_candidate_cache` 与零 token，不创建新的提供商调用台账。`reuse_candidates:false` 强制重新请求；缓存裁剪不影响任务审计与已审核事实。

分析恢复历史按每部文本保留最近 10 次快照；当前分析与有效贡献 ledger 不受该恢复快照裁剪影响，历史恢复仍同时恢复对应贡献和人工覆盖。

审核通过后通过已有 DataStore 的同一事务写素材与 `analysis_commits`。即使主库已提交、任务库尚未标 approved 就退出，再次审批也只返回原映射。关联现有作品时保留其人工字段；新人物和桥段关系仍遵守主库约束。已关联全文的作品 ID 受到删除保护。

## 导出与恢复

`library_exchange.py` 负责主界面的整库交换，和 `csvio.py` 兼容接口分离。交换格式版本 1、schema 6 默认携带 `works`、`characters`、`cliches` 三张主表；存在数据时额外携带手工 `material_relations`、`legacy_values`、`catalog_field_archive` 与 `character_contexts`。派生 `library_links`、`work_cliches` 不作为新格式的独立必填表。DB／CSV ZIP／XLSX 使用同一份内容与 manifest；旧 schema 3、4、5 导出仍支持迁移。schema 4 的固定列集保留，新桥段分类补空后参与当前记录比较；原清单哈希按入站版本的列投影校验，避免未修改的旧包产生错误警告。业务 ID、字符串值和关联对象保持原样，目标库独立管理 revision。

原始最新三张 CSV 无需清单，按精确表头识别，必须同时提供三类数据。导出的包使用共享 `bundle_id`、每表字段／行数／哈希及批次／schema 字段，清单声明的附表也必须保留；预览指出缺失的表、具体字段、关系 ID、双向声明冲突与疑似混用版本的文件。导入先只读解析，再在临时库模拟完整写入；确认时核对素材修订与关系快照，最后在主库事务中应用冲突策略和关系索引。数据库读取拒绝触发器／视图／虚拟表；Excel 不执行公式或外部链接，错误可定位到单元格。

可移植 DB 只含普通数据表与 `_manifest`；CSV ZIP 保存三张主 CSV、实际存在的附表与 `manifest.json`；XLSX 保存同样的数据工作表及 `_manifest`，必要时用 `_long_text` 分片保存超长或 XML 不适宜文本。空主表仍有表头。旧 v8 CSV API 保留，单独的 `/api/library/export/legacy` 使用迁移时归档生成原字段快照，缺少归档的现代记录会明确报错，不猜造旧字段。

全部业务表导出提供内部表 CSV 查阅，BLOB 使用 hex；恢复项目使用 SQLite backup API 生成的一致文件快照，包含五个数据库及原始素材导入文件，并附大小和 SHA 清单。统一上传、分析或转换任务结束或取消后才可备份。素材库交换不包含全文、分析与历史，完整项目备份才用于迁移这些内容。

恢复验证归档路径、大小、哈希与 SQLite 完整性，创建独立目录，保留当前项目；从恢复正文和元数据重建章节文件，重建失败则不发布该恢复目录。会话 Key、系统密钥库内容、环境变量值、运行锁、日志、安装环境与模型权重不进入备份；非秘密的模型配置与凭据引用元数据可以保留。数据库与完整项目备份包含原件、正文和分析结果，未整体加密，不能把 Key 隔离等同于全文加密。接口详见 [api-contract.md](api-contract.md)，运行与验证见 README 和 [validation.md](validation.md)。

## 环境与分发

`scripts/manage.py` 统一处理 `install`、`open`、`doctor` 与 `exec`。源码需要 Python 3.11–3.13、Node.js 22／24；默认创建项目 `.venv`。`--current-environment` 明确复用开发者当前解释器，`--conda-environment`／旧 PowerShell `-EnvironmentName` 只查找已有 Conda 环境，不创建环境、修改全局配置或自动下载系统工具。运行依赖默认不包含测试依赖；`--dev` 与 `--mineru` 分别选装。

安装成功后记录前端源码／资源／依赖清单／构建配置的内容指纹，放入被 git 忽略的构建目录。源码启动重新比较指纹，过期时用已有依赖执行前端构建并展示进度；依赖缺失或构建失败则给出安装指引并停止，避免继续显示旧版 GUI。启动不执行 npm 安装。`doctor` 区分 current、stale、missing 和 prebuilt；没有源码的预构建包仍可直接使用。

`manage.py` 在实际目标解释器中检查 `packaging` 的 METADATA／RECORD 与导入版本，正常环境不强制覆盖。已损坏的单包先隔离旧 metadata，以锁定版本 `--ignore-installed --no-deps` 定向修复，核验后才执行普通应用依赖解析；失败恢复 metadata 并停止，不把忽略依赖规则扩散到整个安装。原生开屏及窗口背景统一蓝色，兼容深色与 reduced-motion。

Windows 通过 PyInstaller 生成应用目录和 ZIP，可选 Inno Setup 安装程序；macOS 在对应架构的 Mac 上生成 `.app` 和 ZIP，可选 DMG，最低系统版本为 macOS 13。包内包含前端、Python、pywebview、LangGraph SQLite 和相应系统凭据后端，不打包用户资料、MinerU 或权重。Windows 依赖 WebView2 Runtime，macOS 复用系统 WebKit；macOS 包添加并验证本机 ad-hoc 签名，当前不提供 Developer ID 签名或 Apple 公证。构建与冻结服务烟雾检查不代表原生窗口交互已验收，具体证据以 [validation.md](validation.md) 为准。
