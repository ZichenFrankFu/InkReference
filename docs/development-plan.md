# 开发计划

## 第一批：结构化素材库

建立 SQLite 迁移、FastAPI、React GUI 和 Windows 脚本。支持三张 v8 CSV 自动识别、预览、事务导入、冲突策略、增删改查、关联与导出。使用真实附件验收 536 条作品、1,213 条人物、138 条桥段和 1,155 条作品与桥段关联，并验证完整语义往返。

复用工作先记录来源及许可证，使用离线规则样本确认文本保真和覆盖问题。真实模型比较尚未执行；不同实现应通过统一适配层比较后决定采用范围。

## 第二批：全文与默认分析流程

保留上传原件，为清洗结果、章节及分块建立版本。先支持 TXT，再按需要加入剧本、SRT、EPUB、DOCX；直接视频转写另行排期。

修复旧清洗与分章的尾部丢失和过度删除问题，提供差异预览、可疑乱码位置及重新指定编码。分析读取明确的清洗版本，所有输入块都保存覆盖状态。

使用 LangGraph 打通上传、清洗、分章、人物／事件／桥段提取、证据审核、入库、导出的默认流程。接入本地模型和 API，逐次记录实际用量及重试；无实际计数时明确标为预估或未知。实现持久化 checkpoint、失败块重跑和人工修订保护。

验收要求包括无标题全文和超长章节的完整覆盖、关闭后恢复、失败状态明确、证据可回查，以及重复恢复不会重复写入。

## 第三批：自定义与桌面发布

开放节点开关、提示词、分块、重试、预算和模型配置；之后加入画布编辑与输入输出映射。工作流定义和画布布局分开保存，每次运行固定依赖版本。

提供声明式 Skill 上传、Schema 校验、示例试运行和版本管理。开发者代码插件独立设计，普通提示词包不自动执行代码。补齐完整用量账本、价格配置和项目备份。

打包 pywebview 桌面窗口和 Windows 安装程序，完成实机环境验收，再按需求评估 macOS。

## 复用决策标准

依次比较接口是否可独立调用、是否保留全文、是否支持证据和失败恢复、许可证、维护成本及 Windows 安装成本。基础库优先直接依赖，适合拆分的函数才移植；每段移植保留原始提交与适配记录。

现阶段候选包括 InkOctoBot、novel-graphrag、Storymap、LangExtract 及工作流编辑相关组件。候选调查不等于依赖已经接入，不在尚未验证的情况下宣称中文模型效果。
