# InkReference 使用手册

本手册对应当前源码界面。升级时先更新正在使用的 Git 分支，再运行同一环境下的安装和启动入口；只拉取 `main` 不会获得尚未合并的开发分支功能。验证范围见 [validation.md](validation.md)。

## 安装与启动

### 桌面包

| 系统 | 打开方法 |
|---|---|
| Windows x64 | 安装 Setup，或完整解压 ZIP 后运行 `InkReference.exe`；需要 Microsoft Edge WebView2 Runtime。 |
| macOS 13+ Apple Silicon | 解压 arm64 ZIP，将 `InkReference.app` 放入“应用程序”后打开。 |
| macOS 13+ Intel | 使用 x86_64 ZIP，打开方法相同。 |

桌面包包含运行依赖，无需 Python、Node.js 或 Conda。MinerU、OCR 权重和本地模型独立安装。macOS 构建目前使用 ad-hoc 签名，首次打开的系统提示及正式签名范围见 [README](../README.md)。

### Windows PowerShell：源码

在包含 `README.md` 和 `scripts` 的仓库根目录执行。默认安装到项目 `.venv`：

```powershell
.\scripts\install.ps1
.\scripts\open.ps1
```

开发者已手动激活 Conda 或其他环境时，安装和启动都选择当前环境：

```powershell
conda activate InkReference
.\scripts\install.ps1 -CurrentEnvironment
.\scripts\open.ps1 -CurrentEnvironment
python scripts\manage.py doctor --current-environment --json
```

也可显式指定已经存在的 Conda 环境；脚本不会创建或初始化 Conda：

```powershell
.\scripts\install.ps1 -CondaEnvironment InkReference
.\scripts\open.ps1 -CondaEnvironment InkReference
```

常用启动选项：

```powershell
.\scripts\open.ps1 -Browser
.\scripts\open.ps1 -Browser -NoOpen -Port 8010 -DataDir 'D:\Writing\InkReference'
python scripts\manage.py doctor --json
```

`-Browser` 使用浏览器；默认使用桌面窗口。`-NoOpen` 保留本地服务而不自动打开窗口，终端会打印地址。自定义端口或数据目录不改变现有默认目录的数据。

### macOS：源码

```bash
./scripts/install.sh
./scripts/open.sh
```

复用已激活的环境：

```bash
./scripts/install.sh --current-environment
./scripts/open.sh --current-environment
python scripts/manage.py doctor --current-environment --json
```

```bash
./scripts/open.sh --browser --no-open --port 8010 --data-dir "$HOME/Writing/InkReference"
python scripts/manage.py doctor --json
```

源码安装需要 Python 3.11–3.13 与 Node.js。安装脚本检查环境和前端指纹；依赖缺失或构建失败时停止启动，避免继续显示旧前端。更多解释器、构建和 MinerU 选项见 [README](../README.md)。

## 工作区

| 入口 | 功能与常用操作 |
|---|---|
| 作品库 | 作品、人物、桥段的新增、查询、筛选、排序、分页、编辑、删除；查看关系；整库导入导出。 |
| 文本清理 | 上传 TXT／EPUB／PDF；更新或补充；元数据；分卷、章节识别；正文编辑、标记、批量清理；完成清洗和导出。 |
| 参考作品分析 | 浏览、修改已确认的剧情大纲、角色、设定、时代背景事件、语言分析；作品笔记、分析历史与原文定位。 |
| 提取任务管理 | 固定版本／章节范围的三模式提取、切块、任务控制、候选审核、重复结果复用、模型 A/B。 |
| Agent 与 Skills | 固定四阶段流程的提示词、模型和预算；上传声明式 Skill；保存不可变流程版本。 |

| 快捷修复 | 生成诊断、整理修复方案、预览差异、源码修复／回滚、章节读模型重建。 |
| 外观 | 浅色、深色、跟随系统；侧栏收展与窄屏导航。 |

## 三模式操作

需要判断和组织内容的功能使用“自动／半自动／手动”入口，输出仍由对应业务合同校验。固定规则的编码检查、章节正则、下载、文件转换、向量计算和 CRUD 不调用语言模型作决定。

| 模式 | 操作顺序 |
|---|---|
| 自动 | 选择已配置模型及本次目标 → 生成 → 查看候选 → 编辑 → 确认保存或入库。 |
| 半自动 | 生成并复制提示词 → 在网页模型中运行 → 粘贴完整回复 → 解析 → 编辑预览 → 确认。 |
| 手动 | 使用字段模板建立草稿 → 填写或调整各项 → 校验预览 → 确认。 |

半自动时保留提示词内的协议、会话标识、ID 与来源字段；不要粘贴推理过程替代结果。网页模型的 token 不由应用统计，显示为未知。自动模式每次应用内调用及重试独立计入用量。预览和选中 A/B 方案不会直接批准事实。

## 作品、人物与桥段

### 新增与更新资料

1. 在作品库点击“新增作品”，选择模式。
2. 自动／半自动填写作品名和作者，可附整理要求；自动选择生成模型、搜索服务及向量连接。应用核对作品身份，保留不同作者和版本。
3. 查看来源、作品字段、主角／主要配角和最多三个桥段。半自动没有向量服务时逐项人工确认现有桥段匹配；有向量服务时可进行真实语义匹配。
4. 编辑内容，逐项选择新建或关联现有对象，确认后事务入库。重复桥段优先增加作品与桥段的关系。
5. 手动模式可分别新增作品、角色或桥段，并填写关联。

人工模板中的主要字段：

| 对象 | 字段 |
|---|---|
| 作品 | ID、作品名、类别、作者、发布日期、看过、剧情梗概、讨论热度、商业规模、关联。 |
| 人物 | 稳定人物 ID、角色名、别名、角色定位、性格基调、视觉元素设计、初始状态、阶段状态。 |
| 桥段 | 稳定桥段 ID、内容、人设塑造、剧情机制、关联作品与角色。 |

人设塑造单选强大／智谋／利他／共情／利己／执念／反差／宿命；剧情机制单选信息反转／机械降神／顿悟突破／代价交换。桥段评分由当前库的唯一命中作品热度权重计算，不能用手填分数覆盖公式。

### 资料 A/B

在同一新增弹窗中保留最多四份不同模型的结果。为方案命名，比较来源、热度范围、角色、桥段和评分场景；采纳一份后在审核副本中编辑，再确认入库。原始结果只读；每组只允许一次入库，其他方案仍可查看。

### 查询、关系与修改

作品按类别、看过、文本和分析状态筛选；角色按定位和作品筛选；桥段按两类标签和作品筛选。“看过”可在作品列表直接点选。详情的“信息”编辑字段，“关联”展示关系及其内容，“文本与分析”读取该作品的正文和分析。

保存遇到版本冲突时，保留当前草稿，读取最新记录后重新核对。删除已有关系的记录会明确列出影响；正文已绑定的作品需先处理正文关联。桥段不能关联桥段。

## 文本清理

### 上传与元数据

首次上传 TXT、EPUB 或 PDF 建立文本记录。已有作品在“元数据 → 上传文件”选择“更新正文”或“补充章节”：前者替换当前全部正文，后者接在末尾。上传菜单的“上传其他作品”建立另一部文本，不写入当前作品。

TXT 严格解码；EPUB 按阅读顺序转 Markdown 再转 TXT；PDF 选择 MinerU 文字层提取或 OCR。只有选择 PDF／EPUB 后才显示相应转换选项。上传与转换期间查看标题下进度，可取消或重试。元数据中编辑书名、作者、类别、最早更新时间并查看来源和历史。

### 分卷与章节

先在“分卷与章节”调整目录。分卷自动模式联网读取该作品的分卷资料；半自动复制提示词后粘贴结构化回复；手动填写卷名及起止章。使用章节选择器搜索真实标题和缺章项，预览覆盖范围后保存。

展开“章节标题格式”选择识别格式或填写模板／正则，预览新旧目录差异后选择保留旧版或采用新版。正文标记规则也在本页，默认收起。更换规则不会把两套目录合并。相邻空重号章节可提出修复；两项都有正文时保留供核对。

### 正文与标记

目录显示规范章号和标题，正文不重复标题。红色标记可清理内容；紫色标记需要修正的字符；缺章项单独高亮。点击标记定位到实际标题或正文位置。对红色片段可取消清理，对紫色问题手工改正文。

标题和正文可直接修改；未保存时出现状态和保存按钮。同一次保存提交标题与正文。目录没有批量复选框；打开“批量清理”查看每章实际命中的标题和片段，逐项选择、按章选择或全选，再确认。问题总数按章节计。

缺章逐项保留空白占位，可搜索后补写。垃圾桶删除本章；删除后调整同序列后续编号，保留原有缺号和卷内编号重启。分页编辑保留未显示的正文；切章或离开会保护未保存草稿。

### 完成与导出

保存后选择“完成清洗”，核对关联作品及检查项，固定完成版本，再导出合并 TXT 或逐章 ZIP。TXT 使用规范标题和单换行；尚未补齐的章保留标题。`books/书名/metadata.json` 与各章 TXT 是当前正文的可重建文件投影，手改这些磁盘文件不会自动写回数据库。

## 提取与审核

### 建立任务

1. 在文本清理点击“开始分析”，或在“提取任务管理”选择作品与正文版本。
2. 选择全部正文，或增加多个起止章节范围；重叠／相邻范围自动合并，空章和占位章列为跳过。
3. 选择流程版本与模式；自动模式选择模型，半自动复制各块提示词；手动选择“准备分析”后从阶段字段模板填写。
4. 创建任务后检查切块与实际模型快照，开始生成或导入候选。

“切块”按模型上下文、完整提示词、Schema、输出预留及实体记忆决定，优先保持整章；它与小说分卷不同。所有结果保留全书绝对叙事位置，局部提取不改变进度分母。

### 运行、恢复与去重

黄色暂停符号停止后续调用，蓝色播放符号开始或恢复，红色终止符号停止任务且不可恢复。已发出的响应先持久化，费用和结果不会因暂停丢失；终止后保留已有候选。应用重启不自动调用模型。

相同版本、流程、提示词、模型、交互模式和章节范围可返回已有任务。已审核的完整源块可复用；只重叠旧块一部分时保留历史提示并独立提取。手动录入与网页复制粘贴保留不同来源标识，不跨模式套用已审块。关闭复用可明确重跑。候选缓存与任务审计分开，修改模型或提示词不会命中旧候选。

### 提取 A/B

选择 2–4 个不同的实际模型，对同一正文版本和章节范围运行。各模型保留独立候选、调用和用量；切块数量可以不同。比较结果，采纳一份后进入审核。已有正式贡献时不能改选另一模型；另一份结果不被覆盖。

### 审核入库

按固定顺序提取剧情大纲、角色、设定、语言分析，时代背景事件包含在最后阶段。每块候选可查看原文证据、修改、保存修订和独立批准；全部批准前仍是候选。已有人工内容按原有 revision 和贡献规则保护，重复批准保持幂等。

手动模式按顺序填写当前块的四个阶段，可增加事件／角色／设定等条目，数组每页 20 项；“原文片段”填写该块的连续原句，源版本与固定定位由模板保留。每阶段“校验并预览”只保存候选，四阶段完成后再分别“确认入库”。旧合同 2／3 仍可查看和使用原来的粘贴流程，不开放新手工表单。

## 参考作品分析

| 页签 | 查看和编辑 |
|---|---|
| 剧情大纲 | 一句话剧情梗概；故事中时间线／叙述顺序线；事件名、主题、描述、前因与结果、情节线、人物和设定；情节线描述及时间节点。 |
| 角色 | 初始状态及初始人际关系；可命名阶段、经历事件、该阶段身份／能力／视觉／性格／关系变化；阶段范围。 |
| 设定 | 地点、组织、能力体系等稳定 ID；叙事出现点；追加设定指向更早条目。 |
| 时代背景事件 | 网络热梗／热门事件，标题、内容、大致时间、叙事出现点、关联事件和人物、观察频次。 |
| 语言分析 | 本地句长／段长／标点统计；取名风格及姓／名 Top 10；单选视角；附示例的修辞与对白；四类叙述构成；节奏、高潮、爽点、伏笔和情绪。 |

有可靠章节坐标时可用“第 X / Y 章”或百分比；Y 使用该分析正文版本的全书总章节数，包含缺章占位。无章节作品按字数进度。故事时间可空，不用推测日期补齐。

角色阶段关系继承上一阶段，首阶段继承初始关系；以继承结果为基础修改。事件选择不能早于上一阶段叙事边界。最新阶段可延续到“最新章节”。全局人物库与作品分析只在显式导入／绑定后同步，作品之间的状态相互隔离。

“作品笔记”记录评分、喜欢原因和章节笔记；“分析历史版本”预览并恢复旧分析。旧设定集保留原始条目、角色、分类设定与四节 TXT 导入导出，原始条目翻译和旧大纲整理先预览再应用；新分析的五个页签不重新创建旧的分段视图。

在“参考作品分析 → 剧情大纲 → 整理大纲”打开大纲整理；旧设定集的“原始文本 → 翻译与预览”打开翻译。大纲使用已保存的事件作为来源。自动／半自动可压缩或重组文字，沿用已有事件、情节线和节点 ID、时间、来源及关系；手动模式用剧情表单编辑。译文在预览区修改目标文本。三种模式都先预览，最后应用时仍核对分析 revision；子表单尚未保存时不能确认整个预览。自动回复格式不合法时保留原回复，修正并解析不会再次调用模型。生成期间资料发生变化时重新准备。

## Agent、Skill 与模型

在“Agent 与 Skills”选择阶段，修改内容要求、补充提示词、阶段模型、输出上限和预算，保存为新的不可变版本。阶段顺序固定，不能改写输出 Schema 或跳过阶段。Skill 接受 JSON、SKILL.md 或声明式 ZIP；上传内容不作为代码执行。

“模型设置 → 添加模型”填写提供方、地址、模型、上下文、输出上限、超时及可选价格。Ollama、LM Studio、vLLM 使用本地服务；商业 API 使用兼容 Chat Completions 的 HTTPS 地址。可先读取模型列表、测试草稿，再保存。凭据可选当前会话、系统密钥库或环境变量；数据库和备份不保存明文密钥。

“下载向量模型”连接本机已运行的 Ollama，选择模型名后下载；查看字节进度，取消或重试。下载完成后验证 embedding 接口，再添加或复用模型连接。应用不安装 Ollama，权重由 Ollama 管理；下载字节不是 token。

用量区按任务查看调用、失败／待确认、实际／估计／未知 token 及估计费用。价格由用户配置；未配置价格或网页模型用量保持未知。

## 导入、导出与备份

| 目的 | 格式与操作 |
|---|---|
| 交换作品／人物／桥段 | 作品库导入一个 DB、一个 XLSX，或完整 CSV ZIP；也可同时选择三个原始 CSV。先预览缺表、缺字段、关系冲突及文件版本，再按跳过／更新／报错提交。 |
| 输出素材库 | 选择 DB、CSV 或 XLSX。三种格式内容一致；空主表也保留，附表按清单保留。CSV ZIP 不要拆散丢弃清单或辅助表。 |
| 输出正文 | 完成清洗后合并 TXT 或章节 ZIP。 |
| 查阅全部业务表 | 备份页导出每表一个 CSV；它不是可完整恢复的项目包。 |
| 迁移完整项目 | 导出完整 ZIP；恢复时选择独立工作区，检查 SHA-256、路径、大小和 SQLite 完整性。 |

完整备份包含五个 SQLite 数据库与原始素材导入文件，不包含密钥值、环境、本地模型权重和派生章节文件。恢复后重新配置凭据；逐章文件可由正文重建。不要将正在运行的数据库单独拷走替代项目备份。

## 存储检查与维护

在“备份与恢复 → 存储管理”查看数据库和磁盘可用容量、各库状态；点击刷新重读，点击“优化数据库”执行有限维护。

也可通过本机接口查看数据库／WAL 大小、可复用页和缺失索引。默认端口为 8000，使用其他端口时替换以下地址。PowerShell：

```powershell
Invoke-RestMethod -Uri 'http://127.0.0.1:8000/api/studio/storage'
Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8000/api/studio/storage/optimize' -ContentType 'application/json' -Body '{"database":"all"}'
```

macOS：

```bash
curl --fail 'http://127.0.0.1:8000/api/studio/storage'
curl --fail --request POST 'http://127.0.0.1:8000/api/studio/storage/optimize' --header 'Content-Type: application/json' --data '{"database":"all"}'
```

维护补齐适用索引、更新有限优化器统计并进行被动 WAL checkpoint，不删除业务记录或执行 VACUUM。任务运行时返回冲突；繁忙或达到每库执行预算时返回 `deferred`，稍后再试；真实 SQLite 故障返回 `error` 和诊断 ID，按 ID 排查。数据增长和仍存在的容量上限见 [架构](architecture.md) 与 [审查报告](review-v13.md)。

## 故障处理

先保留未保存的草稿，记录发生的工作区与操作，再打开左侧“快捷修复”。检查诊断和结果预览后确认；源码修复会保存原文件，运行固定语法／类型／构建检查，失败回滚。后端或脚本修改后需重启；打包版可导出源码方案或重建章节读模型，不直接替换可执行文件。

| 模式／入口 | 具体操作 |
|---|---|
| 自动 | 填写功能位置与问题／预期结果，选择“修复模型”，生成方案；编辑返回 JSON，点击“检查修复方案”，核对差异后应用。 |
| 半自动 | 生成诊断提示词，复制给网页模型，将完整修复 JSON 粘回；检查、修订、预览与应用。 |
| 手动 | “准备修复模板”后填写变更摘要，选择源码文件，查看锁定的 SHA-256 与只读原文件；逐处填“原代码／替换代码”，需要时增加文件或替换项，再检查与预览。 |
| 本机恢复 | 打开已有生成记录、回滚源码操作，或选择作品重建章节索引。生成列表只读摘要，点开一条才载入完整草稿。 |

自动生成可取消，已返回回复和用量仍保留；重新打开保存回复后需重新检查生成预览。诊断会话和预览两小时有效，源码已经更改时须重新生成诊断；哈希检查不通过不会覆盖当前文件。语法／构建检查通过后仍需复测原问题。

| 情况 | 处理 |
|---|---|
| 更新后仍是旧界面 | 确认所在 Git 分支和提交；退出旧进程，在仓库根目录用原环境重新运行安装、启动脚本。 |
| `packaging None`／缺 RECORD | 用同一环境重新运行 `install`；脚本先检查并修复该依赖的损坏元数据，保留本地恢复材料。不要混用默认 `.venv` 与 `-CurrentEnvironment`。 |
| 缺少 `defusedxml` 等依赖 | 用启动时相同的环境选项安装；通过 `doctor --json` 核对实际解释器。 |
| 端口被占用 | 退出旧实例或指定 `-Port`／`--port`；同一数据目录不并行启动第二实例。 |
| 桌面窗口无法打开 | 检查 WebView2／WebKit 依赖；用 `-Browser`／`--browser` 打开同一应用。 |
| 模型超时或 JSON 不合法 | 核对服务、模型、上下文和输出上限；保留失败调用，在预览中修订或重试对应块。 |
| 分卷来源与作者不符 | 核对作品名／作者；重新搜索，或使用半自动／手动计划。 |
| 保存冲突 | 保留当前草稿，读取最新版本后重做确认；不要反复提交旧 revision。 |
| 章节磁盘文件缺失 | 使用章节文件校验／重建入口；SQLite 已提交正文仍是权威。 |

使用当前环境时，`doctor` 同样添加 `--current-environment`；显式命名环境使用 `--conda-environment NAME`。日志字段、路径、保留上限与诊断 ID 见 [日志与故障定位](logging.md)；容量、索引与清理边界见 [架构](architecture.md)。
