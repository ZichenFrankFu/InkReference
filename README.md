# InkReference

Windows／macOS 本地写作参考数据库应用：管理作品、人物和桥段，清理与编辑文本，使用固定阶段的 LangGraph 工作流提取编年史、动态角色、设定、语言分析和时代背景事件，审核后关联到作品。各阶段可通过 Agent／Skill 调整内容要求，输出结构保持统一。

普通用户使用打包后的桌面应用，无需安装 Python、Node.js 或 Conda。源码安装默认使用项目内 `.venv`；开发者可自行配置并复用 Conda 或其他 Python 环境。

首次使用见 [完整使用手册](docs/gui_manual.md)。排查报错见 [日志与故障定位](docs/logging.md)；上一轮架构审查、容量边界与待优化项目见 [审查报告](docs/review-v13.md)。

## 当前功能

| 工作区 | 已实现的功能 |
|---|---|
| 动态功能三模式 | 作品资料、分卷、作品特征提取、快捷修复与资料翻译使用自动／半自动／手动交互；自动和半自动先打开双栏弹窗，左侧编辑实际提示词，右侧编辑生成或粘贴的回复，可为本次操作选择模型。确认发送才调用模型，校验与预览后确认才保存或入库。手动使用字段模板。固定规则、格式转换、下载及 CRUD 保持本地确定性处理。 |
| 作品库／角色库／桥段库 | 支持跨三库检索元数据和显式关联，结果分为作品、角色、桥段三组。作品增加题材、风格，可按类别、题材、风格、看过、已上传正文、已完成解析筛选，并按讨论热度或商业规模排序；角色按角色定位及关联作品筛选，桥段按人设塑造、剧情机制及关联作品筛选；筛选先于分页。完成解析要求当前正文的完整四阶段结果均已审核，局部或旧版本分析不算完成。“看过”在列表中点选是／否。关联只在“关联”页显示，保存目标 ID、关系说明与额外字段；桥段不能关联桥段。编辑检查 revision，同名作品不自动合并。 |
| 桥段分类 | “人设塑造”和“剧情机制”两个独立单选字段，列表与详情显示完整标签，例如 `人设塑造·强大`、`剧情机制·信息反转`；旧数据可暂未分类。分类值通过 CRUD 与整库导入校验，并随 DB／CSV／XLSX 导出保留。 |
| 整库导入 | 默认一个 `.db`；也可同时选择最新作品／角色／桥段三个原始 CSV、完整导出 ZIP，或一个 `.xlsx`。按表头识别，不依赖文件名；预览指明缺失表、字段、引用 ID、双向关系冲突及疑似混用版本的文件。旧 v8 完整三表及结构版本 3、4、5、6 的导出包仍可迁移；缺失的新分类字段保持空白。预览通过后按跳过、更新或报错整批事务提交。 |
| 整库导出 | DB、CSV、XLSX 使用同一内容，默认只有作品／角色／桥段三张主表与清单；存在手工关系或旧字段归档时才附带相应辅助表。CSV 使用 UTF-8 BOM；Excel 的编号、日期及正文按文本保存，超长内容用辅助工作表保留。旧版迁移快照另有明确兼容导出接口。 |
| 全文上传与更新 | 主界面只接受 TXT、PDF、EPUB。作品库是新增作品的入口；“元数据”中的“上传文件”直接针对当前作品，不带新增作品下拉菜单。选择“更新正文”替换当前全部正文，或“补充章节”接到末尾，无需再次选择保存位置。正文清理与参考分析的左侧列表统一为“参考作品库”，字数按万字保留一位小数，类型读取作品类别。PDF／EPUB 自动转为 TXT；处理阶段有进度、取消及重试。旧原件与版本保持不可变。 |
| 逐章 TXT 存储 | 数据目录的 `books/书名/` 为每章保存一个 UTF-8 TXT，并保存 `metadata.json`；元数据包括书名、作者、最早更新时间、作品类型、正文版本、章节顺序及校验值。同名作品使用文档 ID 后缀分开，非法文件名做跨平台替换。支持章节 ZIP 与全书合并 TXT；文件由已提交正文生成，可校验与重建，不把导入日期冒充首次更新时间。 |
| 正文清理 | 按“元数据 → 分卷与章节 → 正文清理”排列；上传、编辑信息和版本历史集中在“元数据”；正文标记规则与章节标题格式默认折叠，选择格式后预览分章变化。正文只加载目录和当前章，版本历史按需读取；页面标题下用单一进度区域反馈状态，支持减少动态效果。保留“开始分析”和任务进度；“完成清洗”后进入检查与 TXT 导出。 |
| 逐章清洗 | 目录按问题类型高亮整项，缺章占位用独立颜色标记；标题与正文内显示实际命中的红色清理片段、紫色字符问题，图例集中展示。红色与紫色片段均可快速定位到标题或正文的实际分页；结构问题显示具体原因，不可见字符也有可见标记。默认非正文关键词包含 `PS：`。目录不带复选框；“批量清理”弹窗按章节展示真正命中的标题及正文片段，可逐片段选择、按章选择或全选。同章多个问题只算一章。损坏字符由用户修正，缺字不会靠猜测补全。 |
| 章节编辑与识别 | 自动识别中文章／回／节、Chapter、数字编号；识别格式、自定义模板／正则、非正文关键词及杂字规则统一放在“分卷与章节”。目录显示“第X章 标题”，正文不重复章号和标题，不保留连续空行。缺号逐章显示空白占位项，可搜索后补写。标题和正文均可编辑，修改后显示未保存状态与保存按钮；同次保存原子提交标题与正文。支持插入、外露删除按钮与历史恢复；删除后调整同序列的后续章号，保留原有缺号与卷内编号重启。重识别先预览目录差异，再选择旧版或新版，可处理相邻空重号标题。普通正文编辑只重算受影响章节。 |
| 分卷与章节 | 提供自动／半自动／手动模式：自动使用已配置的模型 API 和搜索服务检索分卷并独立读取来源；半自动复制联网提示词、粘贴网页模型回复并校验预览；自动与半自动使用相同的提示词与回复双栏；手动只编辑卷名和章范围。三种方式均先预览再保存，方案固定到正文版本，检查连续覆盖与 revision。章节识别格式及正文标记规则保持默认折叠。 |
| 上传内格式转换 | EPUB 按 spine 阅读顺序转 Markdown，再得到纯文本；PDF 使用本地 MinerU 4 提取文字层，或使用 Standard OCR 识别扫描页。转换并入上传流程，完成后自动解析章节。已有转换 API 继续保留 Markdown／TXT 输出，主界面以清洗 TXT 为导出结果。 |
| 模型设置 | 完整 GUI 配置本地 Ollama、LM Studio、vLLM 和兼容 OpenAI Chat Completions 的商业 API；配置地址、模型、凭据、上下文、输出上限、超时及价格；主动读取模型列表、测试当前草稿和管理已存凭据。 |
| 三模式新增 | “新增作品”弹窗内选择自动／半自动／手动，无独立 AI 更新页面。自动交由应用内模型核对已有作品并联网读取来源，生成作品／主角与一名配角／最多三个桥段草稿，经真实 embedding 匹配去重；半自动生成结构化联网提示词，粘贴网页模型回复，离线解析后人工审核去重，也可显式启用来源复查和向量模型；手动分别填写作品、角色、桥段和关联。确认后事务入库，不生成正文或正文分析。 |
| 新增资料 A/B 对比 | 在同一新增作品弹窗中保存最多四份不同应用模型或网页模型的原始结果，分别命名、查看来源、热度区间、桥段评分场景与用量。原稿只读，采纳后创建可编辑审核副本；每组仅允许一次原子入库。外部网页模型用量标为未知，不冒充零 token。 |
| 本地向量模型下载 | “模型设置 → 下载向量模型”连接已运行的本机 Ollama，使用真实流式下载进度显示字节／百分比；下载完成后验证 embedding 能力，再添加模型连接。可取消、重试，已有同连接模型会复用；权重由 Ollama 管理，应用只保存有界任务信息。 |
| 作品解析 | 浏览已确认的剧情大纲、角色、设定、语言分析与时代背景事件；已有内容和任务管理分为独立页面。作品详情的“文本与分析”按需读取关联正文及分析，可定位原文。分析侧栏不再提供重复的导入与新建设定集入口。 |
| 编年史与动态事实 | 事件以平面列表记录名称、主题、描述、叙事进度和可选故事时间，可切换故事中时间线／叙述顺序线；前因、结果、角色、设定和情节线使用稳定 ID。角色初始状态与事件驱动的完整阶段快照统一，设定可引用更早设定作为追加设定，并以追加链展示。剧情开头为一句话“剧情梗概”，情节线保存描述及时间节点；界面不再显示卷级与全书大纲。 |
| 语言分析与时代背景事件 | 本地计算句长、段长、标点频率；取名风格合并规律和示例，并按角色姓名统计姓、名用字 Top 10；叙述视角单选第一人称／有限第三人称／全知第三人称。对白风格与修辞习惯附原文示例，动作／外部描写／心理／背景说明按百分比分配。保留高潮、爽点、伏笔、节奏、情绪分析；时代背景事件记录网络梗／热门事件、大致时间、叙事出现点、关联事件与人物及观察频次。 |
| 任务管理 | 汇总提取、资料检索、模型下载、分卷检索、上传、转换、修复与提示词任务，支持类型、状态、搜索、分页及已终止页签。暂停、终止后保留进度和已有结果，模型任务恢复后继续核对提示词；下载、上传和转换按原任务重试。提取仍固定“剧情大纲 → 角色 → 设定 → 语言分析”，支持章节范围、分区审核、当前来源证据、历史与 2–4 模型 A/B。旧版素材审核与设定集数据兼容保留。 |
| 设定集兼容 | 保留原始文本、静态角色、分类设定及核心冲突／高概念的数据与 API；四节 TXT 合并／替换导入导出，保留多行和未知字段。原始条目翻译先预览后应用；不再从参考分析作品列表创建设定集。 |
| 作品笔记与分析历史 | 保存个人评分、喜欢原因和章节笔记；文本普通历史最近 10 版，初始／当前／被任务或审核等引用的版本另保护；章节缓存最近 3 版。分析恢复快照最近 10 次，逐节审核状态和人工风格修订同步恢复。资料翻译支持提示词／粘贴或模型调用，使用统一用量台账。 |
| Agent／Skills | 内置 `default@4.0.0` 固定流程；按阶段调整提取重点、提示词、模型、输出上限、token 预算与已上传 Skill，保存不可变版本；阶段模型可继承任务模型。统一输出 Schema 不可改写，不提供跳阶段开关或拓扑编辑。支持 JSON、SKILL.md、声明式 ZIP Skill，不执行上传代码；旧 1.0／1.1／2.0／3.0 合同和任务保留固定定义。 |
| 用量与费用 | 每次模型请求及重试独立记账；查看成功／失败／待确认状态、输入和输出 token，区分提供商实测、规划估算及未知；按配置的价格和币种估算费用，可按分析任务筛选。 |
| 存储与增长 | 素材／任务／关系／用量使用版本化索引计划，模型用量分页与 SQL 聚合；桥段评分只缓存小型汇总并按数据库 epoch 失效。可只读检查容量、WAL、可复用页及缺失索引，再显式执行有限优化；不自动删除原件、任务候选或用量。 |
| 备份与恢复 | 导出包含五个 SQLite 数据库及原始素材导入文件的完整项目 ZIP；恢复时校验路径、大小、SHA-256 和数据库完整性，生成独立工作区。全部业务表 CSV 用于查阅和迁移，恢复项目使用完整备份 ZIP。 |
| 快捷修复 | 自动模型、半自动 prompt／paste、手动原代码／替换代码模板均先校验并预览文件差异；不隐式应用模型方案。源码版校验原文件哈希、保存原始字节备份、执行固定语法／类型检查与前端构建，失败恢复，成功可回滚；打包版可重建章节索引或导出源码方案。不执行模型附带命令。 |
| 外观与导航 | 蓝色界面支持浅色、深色及跟随系统，选择在本机保存；窄屏布局、键盘操作与减少动态效果。移除独立顶部横条，侧栏内收展，窄屏菜单进入页面标题行；标题与操作区统一。加载使用标题下呼吸进度轨，有确定进度时显示实际值，不使用右上角加载浮层。正文区填充剩余窗口高度。模型配置集中在“模型设置”，只保留一个“添加模型”入口；侧栏保留“备份与恢复”。 |
| 图标与诊断 | 蓝底白色 R 使用同一图源生成网页、Windows 和 macOS 图标；原生桌面入口与打包使用对应资源。结构化日志保存模块、动作、请求／任务／诊断 ID、阶段、耗时与源码帧；错误可沿诊断 ID 进入快捷修复，不把正文或凭据作为常规日志。 |
| 桌面与运行 | Windows／macOS 桌面应用及浏览器入口；源码一键安装、启动、环境诊断；默认使用项目 `.venv`，也可复用开发者已配置的环境。支持自选端口、数据目录和工作区单实例保护；提供 Windows ZIP／Setup、macOS `.app`／ZIP 构建。 |

## 数据模型

主库迁移版本为 7，当前分析内容合同为 4；历史合同 1／2／3 保留独立定义与原始数据。作品、角色与桥段使用独立 ID；同名不自动合并。人物库和作品人物提取共用角色合同，按人物 ID 与作品 ID 保存各作品阶段状态；首次从提取结果明确导入或绑定后，已有绑定的角色与参考分析可双向同步。 独立素材包缺少来源文档时保留来源 ID 并离线编辑快照，完整正文／分析迁移使用项目备份。

| 数据 | 主键与字段 | 关联方式 |
|---|---|---|
| 作品 | `作品ID`；作品、类别、题材、风格、作者、发布日期、看过、剧情梗概、讨论热度与商业规模区间 | `关联作品`、`关联角色`、`关联cliché` 保存 ID JSON 数组和关系内容 |
| 角色 | `人物ID`；角色名、别名、角色定位、性格基调、视觉元素设计、初始状态与阶段状态 | `关联作品`、`关联cliché`；支持多作品，不用单一作品作为所有权 |
| 桥段 | `clichéID`；内容、cliché 评分、人设塑造、剧情机制 | `关联作品`、`关联角色`；不允许桥段关联桥段 |
| 文本 | document ID、不可变 version ID、来源及清洗完成版本 | 显式 `work_id`，一部作品可关联多个文本 |
| 参考分析 | document ID、revision、分区与审核贡献；新分析内容 Schema 4 | 用户时间坐标统一为叙事进度／阶段范围与可选故事时间；事件、情节线、角色和设定使用稳定 ID，内部保留原文证据及来源版本；旧格式保留兼容 |

界面的“看过”对应 CSV 的 `用户是否完整体验过` 字段；旧字段经迁移归档，剧情补充说明和典型桥段剧透不再显示为当前作品字段。`library_links` 是由主记录关联字段事务重建的查询索引；手工关系的额外信息另存于 `material_relations.metadata_json`。完整结构和版本保留规则见 [架构](docs/architecture.md)，上游机制、采用方式和未移植范围见 [InkOctoBot 对照报告](docs/reference-parity.md)。

桥段的两个分类字段分别单选，也可留空；不推断旧记录的分类，不把多个选项拼入同一字段：

| 字段 | 选项 |
|---|---|
| 人设塑造 | 强大、智谋、利他、共情、利己、执念、反差、宿命 |
| 剧情机制 | 信息反转、机械降神、顿悟突破、代价交换 |

桥段评分为 `100 × 命中唯一作品的热度总和 ÷ 全库唯一作品的热度总和`。作品热度取讨论热度与商业规模两个 1–10 区间中点的平均；缺失分项按 1，旧数据的有效单一热度继续兼容，并返回缺失热度数量。分数表示当前素材库中按热度加权的普及程度，不是全网出现率或文学质量分。人物与桥段的关联双向同步；详情中不再提供“使用桥段”或旧命中统计操作。

导入文件中的 `cliché评分` 原值（包括空白）保留在原始记录存储；界面及规范 DB／CSV／XLSX 导出使用当前库公式的实时计算值。因此，派生评分不承诺逐字等于输入值；其他非派生字段、顺序与关系按交换合同保留，重新导入规范导出应保持稳定。

## 普通用户：桌面应用

从项目提供的构建产物中选择与系统匹配的包：

| 系统 | 安装与打开 |
|---|---|
| Windows x64 | 运行 Setup 安装程序，或完整解压 Windows ZIP 后双击 `InkReference.exe`。Windows 需要 Microsoft Edge WebView2 Runtime。 |
| macOS 13+ Apple Silicon | 解压 `macos-arm64` ZIP，把 `InkReference.app` 拖入“应用程序”后打开。 |
| macOS 13+ Intel | 选择 `macos-x86_64` ZIP，按相同方式安装。 |

可携带版需要保留整个解压目录。macOS 包按对应架构在 Mac 上构建，构建会添加本机 ad-hoc 签名，未提供 Developer ID 签名或 Apple 公证；首次打开可能需要在“系统设置 → 隐私与安全性”中允许此应用。GitHub Actions 的构建产物位于相应运行的 Artifacts，构建不会自动发布 GitHub Release。各平台的实际验证范围见 [validation.md](docs/validation.md)。

首次使用：

1. 打开“作品库”，导入一个 `.db`、完整 CSV 文件包或 `.xlsx`，检查三类数据及关联验证后提交；也可以直接新建作品。
2. 在“模型设置”选择本地模型或商业 API，填写地址、模型及凭据，测试连接后保存。
3. 在作品库新增作品，再到“正文清理 → 元数据 → 上传文件”处理当前作品。选择替换全部正文或补充章节。转换、章节识别和标记扫描自动衔接，在“正文”编辑标题与正文，或打开“批量清理”核对命中片段并勾选处理，最后点击“完成清洗”导出 TXT。PDF 需要可选的 MinerU 运行环境，见[格式转换与分析](#格式转换与分析)。
4. 在“任务管理”选择正文版本、模型和固定流程配置，开始分析；或创建手工任务，按阶段复制提示词与粘贴结果。远程分析在开始前简洁确认一次目的服务；任务恢复沿用已确认目标。
5. 在任务页面查看证据、修订结果并确认，在“作品解析”浏览已确认的内容。需要迁移或归档时，在“备份与恢复”下载完整项目 ZIP。

## 源码安装与启动

源码运行需要 **Python 3.11–3.13、Node.js 22 或 24 和 npm**。无需 Conda。以下命令都在仓库根目录执行；安装器检查版本，创建或复用项目 `.venv`，安装依赖并构建前端。下载输出与阶段进度会显示在终端。

### Windows PowerShell

```powershell
.\scripts\install.ps1
.\scripts\open.ps1

# 可选：PDF 转换与测试依赖
.\scripts\install.ps1 -MinerU -Dev

# 只使用浏览器
.\scripts\install.ps1 -BrowserOnly
.\scripts\open.ps1 -Browser
.\scripts\open.ps1 -Browser -NoOpen

# 指定端口和数据目录
.\scripts\open.ps1 -Port 8001 -DataDir "D:\写作资料\InkReference"
```

支持 Windows PowerShell 5.1。脚本不修改全局执行策略；若当前策略阻止运行，可只为此次子进程设置：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\install.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\open.ps1
```

### macOS Terminal

```bash
./scripts/install.sh
./scripts/open.sh

# 可选：PDF 转换与测试依赖
./scripts/install.sh --mineru --dev

# 浏览器模式，或指定数据目录
./scripts/open.sh --browser
./scripts/open.sh --port 8001 --data-dir "$HOME/Documents/InkReference"
```

桌面模式使用 macOS 系统 WebKit。浏览器模式复用相同的本机服务。源码启动时保持终端运行，`Ctrl+C` 停止服务；端口占用会提示换端口，不结束其他程序。源码更新后，启动器检查前端内容指纹；构建过期且已有前端依赖时自动重建并显示进度，不再继续打开过期界面。首次安装、依赖变更或提示缺少依赖时重新运行安装命令；启动过程不会自动安装 npm 依赖。

两套入口共用 Python 管理器，也可直接执行：

```bash
python scripts/manage.py install
python scripts/manage.py open
python scripts/manage.py doctor
```

macOS 中如果命令名为 `python3`，将上面的 `python` 替换为 `python3`。`doctor` 检查解释器、依赖、前端及桌面支持，输出具体修复建议；`doctor --json` 可输出结构化结果。创建 `.venv` 时可用 `install --python PATH`／`install.ps1 -Python PATH` 指定基础解释器。安装使用 `requirements-lock.txt` 约束依赖，前端使用 `npm ci` 和生产构建；可选 MinerU 使用独立的 `requirements-mineru.txt`。默认安装运行及桌面依赖，测试依赖由 `--dev`／`-Dev` 选装。

### 复用开发者自己的环境

先手动激活已配置好的 Python 环境，再明确要求使用当前环境。可以是 Conda、虚拟环境或其他受管理的 Python；安装器不会替你创建 Conda 环境、执行 `conda init`，也不改全局配置。

```powershell
conda activate InkOctoBot
.\scripts\install.ps1 -CurrentEnvironment -Dev
.\scripts\open.ps1 -CurrentEnvironment
```

macOS／通用入口：

```bash
conda activate InkOctoBot
./scripts/install.sh --current-environment --dev
./scripts/open.sh --current-environment
# 等价：python scripts/manage.py install --current-environment --dev
```

旧 `-EnvironmentName InkReference` 参数仅兼容复用**已经存在**的命名 Conda 环境，环境不存在时提示手动配置，不再自动创建。旧 `setup`／`start` 入口保留为兼容入口。Conda 是可选的开发者工具，打包后的应用用户无需配置它。

### 更新后仍看到旧界面或安装失败

新版启动器会检查源码与 `frontend/dist` 的内容指纹，过期时使用已有前端依赖自动重建；依赖缺失或构建失败会停止并给出安装指引。旧的已运行服务仍需重启：先关闭旧窗口，并在启动终端按 `Ctrl+C` 停止旧服务，再使用同一套环境参数启动。更新依赖时可完整执行以下流程，例如当前手动激活的 `InkOctoBot`：

```powershell
git pull --ff-only
.\scripts\install.ps1 -CurrentEnvironment
# 等依赖安装和前端构建全部成功后启动
.\scripts\open.ps1 -CurrentEnvironment
```

默认项目 `.venv` 则省略两条命令中的 `-CurrentEnvironment`。旧的独立 `InkReference.exe` 或桌面快捷方式不会随源码 `pull` 更新；源码使用仓库内的启动脚本，打包应用使用新的构建包。

若提示 `pip is missing in project .venv`，而你需要使用已激活的 Conda 环境，请加 `-CurrentEnvironment`；当前 Conda 环境也缺少 pip 时可执行 `conda install -n InkOctoBot pip`。若需要继续使用项目 `.venv`，可在 Windows 执行 `.\.venv\Scripts\python.exe -m ensurepip --upgrade`，然后重试默认安装命令。

安装器会在实际选中的 Python 环境中预检 `packaging` 的版本元数据和 `RECORD`。发现 `packaging None`、缺少 `RECORD` 或冲突的旧元数据时，自动隔离该包元数据，按 `requirements-lock.txt` 的精确版本定向修复并核验，再继续正常依赖解析；失败会停止并恢复原元数据。有效环境不会强制覆盖全部依赖，也不需要手动删除包或修改锁文件。修复后继续使用相同的环境参数启动。

## 快捷修复

侧栏底部的“快捷修复”适用于报错和界面行为不符合预期的反馈：

1. 选择功能位置，填写复现步骤、实际结果和预期结果。诊断包含本机环境、近期请求／错误、诊断 ID、源码位置及相关项目源码；正文、API Key 和请求内容不自动采集。
2. 选择模式：自动使用已配置的模型生成修复草稿；半自动复制诊断提示词，粘贴网页模型返回的 `inkreference.repair.v1` JSON；手动选择文件并填写原内容／替换内容。生成结果均可检查、修改并重新解析。
3. 预览修改文件、具体差异与检查项目。文件已变化或替换内容不唯一时停止，重新生成诊断；自动模式也不直接写源码。
4. 源码版点击“应用修复”后保存原始字节备份，执行 Python／JSON 检查；涉及前端时再运行 TypeScript 检查和 Vite 构建。进度和结果在弹窗中展示。失败自动恢复本次已写入的文件；成功后可回滚。前端构建成功可刷新页面，修改后端或脚本后需重启应用。

修复只针对现有项目源码，不修改资料库、原件、凭据或依赖清单，也不执行模型返回的命令。语法和构建通过后仍需复测发生问题的操作。变更预览是应用入口，不增加重复确认。

打包应用不能直接改写 EXE／APP 内的 Python 或前端源码；可生成诊断并导出方案。开发者在对应版本的源码环境生成新诊断，再粘贴该方案，应用会使用当前会话并重新核对每个原文件哈希，之后按相同流程预览和应用。源码不匹配时应把新诊断交给模型重新生成方案。完整协议与字段示例见 [api-contract.md](docs/api-contract.md#local-diagnostics-and-reviewed-repairs)。

诊断会话与预览有效期为两小时，重启后需重新生成；源码备份与修复记录在应用数据目录的 `quick-repairs` 中保留，可在“本机恢复”中查看与回滚。回滚先核对所有备份，只恢复仍匹配修复前后哈希的文件；有后续修改时停止，不覆盖新工作。“本机恢复”也可为选定作品重建章节索引，只重算派生缓存，保留原件、正文和历史。完整项目资料迁移继续使用“备份与恢复”，修复源码备份与项目备份分别处理。

自动修复生成任务保留最近 24 份记录，可查看进度、取消和重新打开回复；取消保留已经返回的响应与用量，不隐去已发出的请求。重启后中断的生成标为失败，不自动重试。常规日志位于数据目录的 `logs/events.jsonl`，按大小轮转并清理过期文件；报错通过请求／任务／诊断 ID 连接到具体模块、阶段和源码帧。完整字段与查找命令见 [日志文档](docs/logging.md)。

## 模型配置与基本安全

模型连接均在 GUI 的“模型设置”完成。

| 连接方式 | GUI 配置 |
|---|---|
| Ollama | 选择本地 Ollama，默认 `http://127.0.0.1:11434`；先运行 Ollama 并准备模型，然后读取模型列表或填写模型 ID。 |
| LM Studio／vLLM | 启动相应的本机 OpenAI-compatible 服务，选择预设并填写实际地址和模型 ID。权重由推理服务管理。 |
| 商业 API | 选择 OpenAI、DeepSeek、通义千问或自定义兼容服务，填写 HTTPS 地址、模型 ID 和 API Key。当前支持 OpenAI-compatible Chat Completions 协议。 |

可直接测试当前草稿，无需提前保存。点击“读取模型列表”或“测试连接”就会执行该操作，不再弹出二次确认。上下文、输出上限、超时、价格和币种在详细设置中。新建远程分析时只确认一次目的服务和模型，之后该任务的开始／恢复沿用已确认目标；若目标在提交前被其他窗口修改，会要求刷新后重新选择。

凭据可选**系统密钥库**、**仅本次运行**或**环境变量**。Windows 使用系统凭据后端，macOS 使用 Keychain；系统密钥库不可用时可改选会话或环境变量，不写入明文文件。Key 默认遮罩，保存后清空输入框，可在 GUI 清除。API 响应、模型快照、CSV、项目备份及浏览器存储不包含 Key。凭据绑定服务地址，避免更换服务后沿用原 Key；系统密钥库按工作区隔离，移动或恢复项目后重新配置凭据。

应用保留正常的本机安全边界：服务仅监听回环地址，检查 Host 和请求来源，页面使用 CSP 且不加载外部统计或字体。HTTP 可用于本机模型，远程服务使用 HTTPS；工作流关闭远程追踪。CSV、规则清洗、EPUB 转换、导出和备份在本机执行；远程模型分析会把所选全文版本的正文块与提示词发送至所选服务。模型测试只发送固定测试消息。

如选择环境变量模式，在启动前设置变量，再在 GUI 填写变量名即可。通常直接使用系统密钥库更方便。正文、分析结果和备份没有整体加密，请按自己的资料保管习惯保存。

## 新增作品：自动、半自动、手动

作品库的“新增作品”在同一弹窗提供三种模式；角色库与桥段库仍可分别手动新增并选择关联。

- **自动**：填写作品名、作者，选择资料模型、embedding 模型与 Tavily／Brave／SearXNG 搜索连接。应用内模型结合当前库的匹配候选核对作品身份，实际联网检索并读取来源，生成可编辑草稿。发现已有同名同作者作品时明确更新目标，保留不同版本的选择，不按书名擅自合并。主角、讨论证据最强的一名配角和最多三个热门桥段随作品一起审核，确认后在一个事务入库。
- **半自动**：填写作品名、作者后生成带协议和任务 ID 的联网提示词。复制到可联网的网页模型，粘贴其 JSON 回复，应用自动解析、校验引用与本地 ID，再展示与自动模式相同的审核草稿。默认不调用应用内模型，也不声称进行过向量搜索；桥段按精确文本、模型建议与人工选择去重。可选独立读取来源，以及显式选择 embedding 连接执行真正的向量匹配。入库必须确认人工审核。
- **手动**：填写作品、角色或桥段字段与关联，直接执行对应记录的 CRUD 校验；不联网、不调用模型。

自动模式的桥段以真实 OpenAI-compatible `/embeddings` 或 Ollama `/api/embed` 向量做余弦匹配，≥0.90 建议复用，0.78–0.90 人工比较，低于 0.78 为新增候选。相似度是匹配线索；复用只增加映射，不复制桥段。半自动未配置向量时没有相似度分数，不把网页模型的建议当成本机向量结果。

热度仅在来源支持时给出讨论与商业规模的 1–10 区间及换算依据，资料不足保持空值。网页“已读取”表示取回成功；粘贴来源在未独立读取前标为用户提供。引用、最热配角／桥段和作品身份仍需人工核对，不能保证全网排行。草稿保存与批准检查任务和素材 revision，冲突停止写入；不会覆盖已有正文分析的角色阶段状态。聊天与 embedding 请求分别计入用量，搜索服务计费不冒充模型 token。真实模型内容质量和阈值准确率不由合成测试证明。

同一作品可添加最多四份对照结果：应用内模型分别执行，或分别生成网页模型提示词并粘贴回复。每份结果保留标签、原文输出、来源及独立用量；应用不覆盖已经加入对比的原稿。对比热度区间、人物与桥段，并按当前库的统一权重公式展示桥段“新增／复用”评分场景；这是拟入库后的假设结果，不是模型可直接改写的最终计算字段。采纳一份后生成带来源链的可编辑审核副本，仍需人工确认，组内只提交一次，其他原稿保留。网页模型的外部 token／费用无法由应用读取，显示“外部用量未知”；应用的验证／embedding 调用仍独立记账。

### 下载本地 embedding 模型

先安装并运行本机 Ollama，在“模型设置 → 下载向量模型”选择已有本机连接或填写回环地址，输入支持 embedding 的 Ollama 模型名称。应用调用 `/api/pull`，按服务返回的 NDJSON 层字节数显示进度；完成后发送短测试到 `/api/embed`，得到有效向量后才显示“添加模型”。取消可停止读取，失败／中断可重试；恢复实际下载进度由 Ollama 已有缓存决定。下载字节不计为 LLM token，能力测试按服务返回的用量记账。

此入口不自动安装 Ollama、不下载裸 Hugging Face 权重并启动推理服务器；权重留在 Ollama 的模型目录，项目备份不包含权重。源码与打包用户都需要可用的本机服务。当前合成流测试不能代替真实模型下载和硬件验收。

## 格式转换与分析

“正文清理”使用一条连续流程：**上传 TXT／PDF／EPUB → 转为 TXT → 识别章节 → 扫描与编辑 → 完成清洗并关联作品 → 导出 TXT**。

上传、编辑信息、版本历史都在“元数据”。“上传文件”固定当前作品，不必再选择保存位置；新增作品统一从作品库进入。左侧列表只显示书名与一位小数的万字数。选择“更新正文”会用新文件替换当前全部正文；“补充章节”会将新文件接在当前末尾。TXT 可选择编码，PDF 按需选择 MinerU 文字层或 OCR 设置，EPUB 自动按阅读顺序转换。两种上传方式都生成新版本，原始文件字节与保留的版本保持不变。上传后的转换、解析和扫描有阶段与进度，失败可重试，处理中的任务可取消。

工作区依次为“元数据、分卷与章节、正文清理”。元数据展示作品字段、文件来源、上传时间和格式，“编辑信息”与“版本历史”均在此处。章节格式、自定义规则与分卷方案集中在“分卷与章节”；正文标记规则和章节标题格式默认收起，以展开控件、格式选择和预览操作组织。标题下的单一进度区反馈加载，不再同时出现右上角加载弹窗。正文集中显示目录、标题、正文、删章、“批量清理”和“查找替换”入口；替换只针对当前章或全书正文，先预览命中数量与章节，再确认创建新版本；目录没有复选框。开始分析后可查看进度并进入“任务管理”。

目录统一显示“第X章 标题”；正文区只含正文，连续空行折叠为一个换行。章号跳过时，缺少的每一章有独立空白项，例如第 11 章后直接出现第 17 章，会补出第 12 至 16 章的目录占位；可搜索章号、填写标题和正文后保存。占位只用于目录，补写前不会改变历史版本或已有分析任务的章节索引。删除章节后按本编号序列调整后续序号，原有缺号和卷内重启保留；同章号仍有副本时不重复减号。重识别先预览目录、空章和重号变化，由用户保留旧版或采用新版；相邻空重号标题可修复，有效正文不会自动互相合并。

正文图例集中在同一区域：红色为可清理内容，紫色为需手动修复的字符，空章表示待补充；目录整项同步高亮。标题和正文显示原有内容及命中范围，字符问题可定位到所在页，结构问题列出具体原因。“批量清理”弹窗按章节列出标题中的求订阅、求月票等明确提示及正文中的命中片段，可逐片段保留或清理，也可按章选择或全选；确认清理后生成新版本，勾选本身不会删除正文。问题数量按章节统计。编辑标题或正文后出现未保存标识和保存按钮；切章或离开时保护草稿。分页保存原子提交本次标题和正文修改，保留分隔换行及未显示的正文。

完成处理并保存后，点击“完成清洗”，选择已有作品或新建作品，记录当前完成版本后导出 TXT。已有作品关联默认沿用，也可明确更改；作品库详情可查看关联文本与参考分析。最终 TXT 使用规范章号与标题，正文内和章节之间都只使用一个换行；尚未补齐的章节保留空章标题，便于后续补充。原始下载与精确版本下载继续作为兼容 API 保留，不作为常驻界面按钮。

文本普通历史保留最近 10 版，另保护初始／当前及被真实任务、有效审核或保留分析历史引用的版本，因此受保护的历史可能超过 10 版。章节缓存最多 3 版，旧保留版本按需重建；原始上传内容独立保存。重复应用未变化的分章方案不创建新版本，分析可恢复快照保留最近 10 次。

EPUB 按 spine 顺序转换为 Markdown，再渲染为纯 TXT，不需要 MinerU。PDF 使用 **MinerU 4**：默认 `flash + txt` 提取文字层，扫描件使用 `standard + ocr` 并准备对应模型；完整块渲染保留可能被分类为页眉的正文。后端继续保留已有 Markdown／TXT 转换输出 API，GUI 将转换并入上传设置与进度。

源码安装可加 `--mineru`／`-MinerU`。MinerU 及 OCR 权重不随桌面包分发；打包版可连接本机独立安装的 MinerU Python。先在该环境按 `requirements-mineru.txt` 安装，再通过环境变量指定解释器；不要求该环境由 Conda 管理：

```powershell
$env:INKREFERENCE_MINERU_PYTHON = 'D:\Tools\MinerU\Scripts\python.exe'
.\scripts\open.ps1
# 打包版：在同一终端运行解压后的 InkReference.exe
```

```bash
export INKREFERENCE_MINERU_PYTHON="$HOME/.venvs/mineru/bin/python"
./scripts/open.sh
# 打包版：在同一终端执行 /Applications/InkReference.app/Contents/MacOS/InkReference
```

OCR 首次运行可能下载模型，转换能力与当前 MinerU 后端及模型有关。

新建分析使用 `default@4.0.0`，固定流程为：**输入 TXT／EPUB／PDF → 数据清洗 → 分卷与章节拆分 → 剧情大纲提取 → 角色提取 → 设定提取 → 语言分析（含时代背景事件）**。上传、清洗和分章在“正文清理”完成；四个模型提取阶段在“任务管理”运行，阶段顺序不变。首阶段遍历全部选定文本后再进入下一阶段；结果须经审核才进入作品解析。

“Agent／Skills”按阶段调整提取内容要求、提示词、模型、输出上限和预算，可选择已上传的声明式 Skill。阶段模型默认继承创建任务时的模型，也可分别选择已配置的本地模型或 API；创建时固定全部模型快照，对涉及的远程目标集中确认一次，恢复时沿用快照并重新核对当前目标是否改变。输出字段、类型、证据要求和跨 ID 引用契约由应用锁定；不允许改变拓扑或跳过阶段。JSON、SKILL.md 和 ZIP 上传均不执行代码。旧 1.0／1.1／2.0／3.0 工作流和任务快照仍可读取与恢复，不把旧结果伪装为新版。

“剧情大纲”以一句话“剧情梗概”开头，事件只按故事中时间线／叙述顺序线展示；情节线包含描述及有状态的时间节点。角色分为初始状态与可命名的阶段状态，初始人际关系属于初始状态；新增阶段先继承上一阶段关系，首个阶段继承初始关系，再按该阶段变化修改。事件选择受上一阶段叙事边界限制，未结束范围显示“最新章节”。设定不再编辑独立阶段快照，追加设定以稳定父 ID 关联为链。有可靠章节坐标的作品，进度可切换“第 X / Y 章”与百分比；Y 始终是所用全文源的全书章节总数，包含缺章占位，选择部分提取范围不会缩小 Y；无章节时使用字数进度。

“任务管理”的“切块”是适应模型上下文的输入计划，与作品的真实分卷不同。新合同 4 默认允许较大的块，但实际容量同时扣除完整提示词、Schema、输出预留和实体记忆，并受全部阶段模型中较小容量约束；优先保留整章，超长章节再按段落切分，连续覆盖、不截断正文。暂停、恢复、终止使用带颜色的符号；正在返回的模型响应会先持久化，暂停后可继续，终止后保留已完成候选；从任务管理恢复后，先返回提示词审核，再决定下一次调用。

“作品解析”只组织已有内容，提供“剧情大纲、角色、设定、时代背景事件、语言分析”五个页签。左侧“参考作品库”支持书名、作者及类别搜索和清除，显示 `8.4 万字` 及作品类别，不显示 TXT 等文件格式。“任务管理”单独负责新建／运行／暂停／恢复／终止、阶段进度、分块审核和旧素材入库；同一作品可跳转查看相关任务。

剧情大纲采用平面编年史事件列表：事件名、主题、描述、故事中时间与叙事进度；通过稳定 ID 关联前因、结果、角色、设定和情节线，不用篇章／时段卡片包裹事件。故事中时间线对明确日期排序，无可比较时间的事件保留叙述位置；叙述顺序线按原文出现位置排序。有统一递增章号时，叙事进度为出现章号／末章号，分母包含缺章占位；卷内重启或重号改用章节顺序，没有明确分章时用非空白正文字符位置百分比。卷级与全书大纲仅保留旧投影兼容，不在新界面展示。

角色先显示初始状态：姓名、性别（男／女／特殊）、年龄、性格基调单选、视觉设计、身份、能力、性格、外貌和关联其他角色的人际关系。阶段状态合并事件经历与其导致的完整状态快照，包含身份、视觉／外貌、性格、能力、人际关系及事件 ID，每段可取名，使用开始／结束叙事进度，最新阶段结束可空。稳定的别名、角色定位和视觉元素与人物库共用合同；不再展示旧揭露章节、排序键、修正旧状态或关联设定控件。设定以叙事进度与可选故事时间记录，每条追加内容有独立 ID 并指向更早设定，不再提供阶段设定。原文核验字段保存在内部；旧结构与撤销快照保留。

“语言分析”分开呈现本地统计、语言风格与剧情分析。句长、段长和标点频率在本机计算，统计方法、正文版本与覆盖范围随结果保存。取名风格为一个字段，姓和名的 Top 10 按稳定角色 ID 去重后的中文姓名计算，不按全文提及次数计数；不确定的译名、别名和称号不猜测拆分。叙述视角只能选第一人称、有限第三人称或全知第三人称；对白风格和修辞习惯附连续原文示例。动作叙述、外部描写、心理呈现、背景说明四类比例合计 100%；旧数据没有比例时保持未知。高潮、爽点、伏笔、节奏和情绪保留来源。新版界面移除语域、叙述人称、口语化程度、惯用表达与口头禅、语言观察字段。

“时代背景事件”按网络热梗／热门事件记录标题、具体内容、大致时间与逐次叙事出现点，出现点关联事件和人物，可选填故事时间。频次按已审核原文位置去重；角色玩梗只统计网络梗在对白和心理中的使用，平均包含零使用角色，并列展示最高者。没有可靠时代依据则留空，不显示结束时间、精度或核实状态；来源读取和时代准确性仍需人工核对，计数也不保证无遗漏。

超长正文优先使用已确认的真实章节边界（含自定义标题规则），超长章再以段落兜底切分，源范围连续无重叠。每次请求按实际阶段模型的上下文预留固定 Schema、系统提示词、输出和自适应实体记忆，记忆最多 6000 codepoint；后续分块传入稳定 ID、短事实和邻近事件，不反复传入整部累计分析，也不传入后文事件与状态摘要。v4 默认目标上限为 400000 codepoint、单次输入 token 1000000、输出 16000，实际仍受已选模型容量与配置预算限制，不把实际作品分卷作为切块硬边界；旧 v3 任务保留原计划。四个语义阶段分别覆盖文本，不将优化宣传成固定比例的 token 节省；实际 token 与每次重试单独计入用量。

提取支持多个章节范围，重叠或相邻范围先求并集；空章及缺章占位列为跳过，提取仍使用全书绝对位置。相同正文版本、固定工作流／Skill、实际模型快照与范围返回已有任务；变更模型、提示或范围会形成独立任务。已审核且源区间、配置签名完全一致的整块可复用；只命中旧大块一部分时不裁剪或冒充新结果，显示历史重叠并独立提取。可关闭复用明确重跑。

提取 A/B 使用 2–4 个不同的实际阶段模型目标，在同一不可变正文版本和原始章节范围上分别运行、保留各自输出与用量；各方案从相同初始实体记忆开始，不借用普通任务已经提取的局部结果。仅修改显示模型名而所有阶段仍指向相同目标的方案会被拒绝。可并列查看候选、按 revision 选择一份进入现有审核流程；选择方案本身不等于已批准事实，也不会抹掉其他模型结果。必须先采纳方案再分区审核或整体入库；已有正式贡献后不能改选另一模型。章节范围与提取 A/B 只对新合同 4 提供，历史合同和旧任务不重切。

“复用完全相同的候选”只命中正文、完整提示词／上下文／Schema、模型快照及输出上限均一致的本地缓存；提示词或模型改变即重新提取。缓存候选重新验证引用 ID 与原文证据，重绑当前正文版本及绝对偏移。双栏提示词提交会保留实际模型与提示词摘要，并退出旧固定提示词的跨任务复用，避免把修改后的结果当成旧方案。缓存命中记录为本地复用，token 为零，不伪装成新的提供商请求。缓存最多 1000 条／32 MiB，不删除原任务审计；关闭该选项可强制重新调用模型。用户审核修改不会写进模型候选缓存。

旧设定集的原始条目、角色、设定与特征仍可查看和编辑，兼容导入导出 API 保留；参考作品库列表不再提供新建设定集入口。翻译先预览后应用，大纲概括保留兼容 API；已有未经新版契约验证的数据不会自动变成有证据的新事实。

作品标题旁的“作品笔记”保存评分、喜欢原因和章节笔记；“分析历史版本”可恢复以前的作品分析，恢复后仍可继续修改和审核。当前复刻范围与尚存差异（例如自动编码往返修复、逐上传文件范围删除）见 [逐项审查](docs/reference-parity.md)，不会把缺字诊断当成已经恢复了原文。

LangGraph 持久化每块响应与 checkpoint。失败、暂停或关闭后可手动恢复，终止后需显式恢复并审核下一次提示词，完成块不会重复请求，重启应用不自动调用模型。模型素材候选附原文引用及位置，修订和确认入库后才写入素材表；已有作品的人工字段保持原值。每次请求与重试单独统计 token，区分提供商实际计数、规划预估和未知值。费用根据配置价格估算；取消会在当前请求边界停止后续调用，已经发出的请求仍可能计费。

## 数据与导出

| 系统 | 默认数据目录 |
|---|---|
| Windows | `%LOCALAPPDATA%\InkReference` |
| macOS | `~/Library/Application Support/InkReference` |

可用 `INKREFERENCE_DATA_DIR` 或启动参数 `--data-dir`／`-DataDir` 指定目录。数据与源码、应用包分离，数据库启动时自动迁移；同一目录只允许一个应用实例。

当前正文同时生成 `books/书名/metadata.json` 与逐章 TXT。文件按清单顺序排列，磁盘文件名包含章节顺序、标题及内容哈希；同名作品以文档 ID 后缀区分。元数据保存书名、作者、最早更新时间、作品类型、导入时间、文档／版本 ID 和章节校验值；只读取原文开头明确标注的书名、作者与日期，未知日期为 `null`，保留年／月／日原有精度。作品标题旁的“作品信息”按钮打开元数据编辑窗口，正文完成导出时可选择合并 TXT 或章节 ZIP。

SQLite 的不可变正文与元数据仍是权威存储，逐章文件是可恢复的当前版本投影；直接改磁盘 TXT 不会自动写回正文。保存后先提交正文，再原子发布新清单；磁盘错误不会丢失已提交内容，可通过章节文件接口校验／重建。普通正文小修改只重新读取和编码受影响章节；未改文件复用。自动清理只删除上一清单登记且校验未改变的应用文件，保留用户额外文件和手工修改副本。文件夹不复制全部历史版本，历史从数据库恢复。

记录按外部 ID 识别，同名作品的不同版本分别保留；日期精度、换行、空白和“不确定”等内容保持字符串。所有素材库格式都先预览，校验通过后整批事务提交，可选择跳过、更新或报错。编辑检查 revision，关联记录删除需要明确确认。

“导出素材库”提供三种互通格式：

- **DB（推荐）**：一个 `InkReference-library.db`，包含 `works`、`characters`、`cliches` 与 `_manifest`；存在手工关系或旧字段归档时，另含 `material_relations` 或 `legacy_values`。这是可移植素材数据文件；内部工作数据库通过项目备份迁移。
- **CSV**：一个 ZIP，包含 `works.csv`、`characters.csv`、`cliches.csv` 与 `manifest.json`，只在有数据时附加 `material_relations.csv`／`legacy_values.csv`。导入整个 ZIP 或清单声明的全部文件；空主表仍保留表头。也可直接同时选择最新的三个原始 CSV，无需自己制作清单，文件名可以不同。导出包带批次字段，必须保留其清单和附表。NUL 控制字符会提示改用 DB／XLSX。
- **XLSX**：一个工作簿，包含三张主表、存在数据的附表及隐藏 `_manifest`；长文本必要时保存到 `_long_text`。保留清单声明的工作表及辅助表；公式、被 Excel 改写的日期与错误单元格会得到具体位置提示。

文件格式版本为 1、交换 schema 为 6；可迁移旧 schema 3、4、5 包。导入按 ID 校验表间关系，并保留关联对象的内容和额外字段。缺表、引用缺失或双向声明不符时，预览列出具体文件与 ID，整批不写入。素材库交换保存目录数据和关系，本机 revision 由目标库管理；全文、分析和历史使用完整项目备份。旧 v8 快照导出只使用迁移归档，新建现代记录缺少旧字段时拒绝生成失真的旧表。

其他迁移入口：

- **兼容 CSV API**：原有单表／v8 CSV API 保留给旧集成，主界面使用上面的整库流程。
- **全部业务表 CSV**：素材、全文、转换、Skills、工作流、分析和用量的每张业务表各一个 CSV，用于查阅及迁移。
- **完整项目备份**：五个 SQLite 数据库、原始素材导入文件及大小／SHA-256 清单，可验证并恢复为独立工作区，保留当前项目。逐章 TXT 文件由备份中的正文与元数据在新目录重建，不重复打包该投影。备份不包含凭据值、安装环境或模型权重；恢复后重新配置模型凭据。

`.gitignore` 排除真实 CSV、全文、数据库及 WAL／SHM／journal、密钥、模型权重、日志、缓存、截图、备份和构建产物；提交合成 fixtures、依赖锁及构建脚本。

## 开发与构建

### 开发检查

先通过上面的安装入口添加 `--dev`／`-Dev`。项目 `.venv` 默认使用以下命令：

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe scripts\verify_reuse.py --source-repo "D:\projects\InkOctoBot"
```

```bash
.venv/bin/python -m pytest -q
.venv/bin/python scripts/verify_reuse.py --source-repo "$HOME/projects/InkOctoBot"
```

复用自己的环境时直接用该环境的 `python`。前端检查：

```bash
npm --prefix frontend run typecheck
npm --prefix frontend run build
```

验证自己的最新三表文件，可在同一 Python 环境执行；文件和生成报告保存在本机，不提交真实资料：

```powershell
python scripts\verify_catalog.py 'D:\PrivateCatalog\works.csv' 'D:\PrivateCatalog\characters.csv' 'D:\PrivateCatalog\cliches.csv' --output artifacts\catalog-roundtrip.json
```

脚本分别检查原始字段／顺序入库保真，以及 DB／CSV／XLSX 两轮规范往返、重入幂等和输入字节未变。规范输出的 `cliché评分` 按当前库公式计算，其他字段和顺序严格相等；不能把空白输入评分与实时计算输出不同误报为资料丢失。macOS 使用相同脚本和参数，替换为本机文件路径。

Vite 热更新调试需要为后端显式允许本机开发来源。在第一个终端设置 `INKREFERENCE_DEV_ORIGIN=http://localhost:5173` 后启动 `python -m inkreference --no-open`；PowerShell 用 `$env:INKREFERENCE_DEV_ORIGIN = 'http://localhost:5173'`，macOS 用 `export INKREFERENCE_DEV_ORIGIN='http://localhost:5173'`。第二个终端执行：

```bash
npm --prefix frontend run dev -- --host localhost --port 5173 --strictPort
```

仅开发界面需要该例外，生产包保持同源。接口定义见 [API contract](docs/api-contract.md)，本地 `/openapi.json` 提供请求结构。

### 构建桌面应用

在目标系统和目标架构上构建，不从 Windows 交叉生成 macOS 应用。默认复用项目 `.venv`；开发者手动激活环境后，可显式使用当前环境。

Windows：

```powershell
.\scripts\package.ps1
.\scripts\package.ps1 -Installer
.\scripts\package.ps1 -CurrentEnvironment -Installer -OutputDirectory "D:\打包结果\InkReference"
```

`-Installer` 需要 Inno Setup 6.3+。默认生成 `release\app\InkReference\InkReference.exe`、`release\InkReference-windows-x64.zip`，Setup 位于 `release\installer`。安装程序建立开始菜单入口，卸载时保留用户数据。

macOS：

```bash
./scripts/package.sh
./scripts/package.sh --dmg
./scripts/package.sh --current-environment --output-directory "$HOME/Desktop/InkReference-build"
```

默认输出 `release/app/InkReference.app` 和 `release/InkReference-macos-arm64.zip` 或 `release/InkReference-macos-x86_64.zip`；`--dmg` 额外生成磁盘映像。Apple Silicon 与 Intel 分别构建，最低系统版本为 macOS 13。构建收集前端、Python、LangGraph SQLite、系统密钥库和 pywebview 运行依赖，不包含用户数据、MinerU 或模型权重。macOS 构建使用本机 ad-hoc 签名并验证，正式分发的 Developer ID 签名与公证由发布者另行配置。

打包烟雾检查以 `--no-open` 验证冻结程序的本机服务和前端；不等同于 Windows／macOS 原生窗口的人工交互验收。检查记录和限制见 [validation.md](docs/validation.md)。
